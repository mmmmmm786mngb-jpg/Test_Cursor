## Детальная информация о используемых объектах и модулях

### 1. Внешняя обработка: внИсполнениеСделокТ+2_ДУ

**Модуль:** `ObjectModule.bsl`

**Процедуры и функции:**

1. **ВыполнитьСделкиВПотоках()** - Экспорт
   - Основная процедура блока T3
   - Параметры:
     - `ПроверкаВыполнения` (Булево) = Истина
     - `Отказ` (Булево) = Ложь
     - `Комментарий` (Строка) = ""
     - `Пул` (Неопределено) = Неопределено

2. **РаспределитьЗадачиПоПотокам()** - Экспорт
   - Функция распределения задач по потокам
   - Параметры:
     - `ДатаИсполнения` (Дата)
     - `ЧислоПотоков` (Число)
     - `Пул` (Неопределено) = Неопределено
   - Возвращает: ТаблицаЗначений "Потоки"

3. **ОпределитьНаименееЗагруженныйПоток()**
   - Функция определения наименее загруженного потока
   - Параметры:
     - `Потоки` (ТаблицаЗначений)
   - Возвращает: СтрокаТаблицыЗначений

### 2. Общий модуль: VTB_ОбщийМодуль

**Модуль:** `Module.bsl`

**Процедура:**

**ВыполнитьИсполнениеСделокПоСпискуДоговорДУ()** - Экспорт

- Вызывается из фонового задания
- Параметры:
  - `ПараметрыЗадания` (Структура)
    - `ДатаИсполнения` (Дата)
    - `СписокДоговор` (Массив)
- Внутри вызывает:
  - `БизнесПроцессы.СделкиTn.ИсполнениеПлановойПозиции()`

## Алгоритм распределения (Bin Packing)

**Принцип работы:**

1. Задачи сортируются по убыванию количества задач (от большего к меньшему)
2. Для каждой задачи находится наименее загруженный поток
3. Задача добавляется в этот поток
4. Загрузка потока увеличивается на количество задач

**Цель:** Равномерное распределение нагрузки между потоками

**Пример:**

```
Поток 0: Загрузка = 0
Поток 1: Загрузка = 0
Поток 2: Загрузка = 0

Задача 1: 100 задач → Поток 0 (Загрузка = 100)
Задача 2: 80 задач  → Поток 1 (Загрузка = 80)
Задача 3: 60 задач  → Поток 2 (Загрузка = 60)
Задача 4: 50 задач  → Поток 2 (Загрузка = 110)
Задача 5: 40 задач  → Поток 1 (Загрузка = 120)
Задача 6: 30 задач  → Поток 0 (Загрузка = 130)
```

## Последовательность вызовов

```
ВыполнитьСделкиВПотоках()
    │
    ├─► РаспределитьЗадачиПоПотокам()
    │       │
    │       ├─► Запрос.Выполнить() [SQL запрос к базе]
    │       │
    │       └─► Для каждой задачи:
    │               ОпределитьНаименееЗагруженныйПоток()
    │                   │
    │                   └─► Потоки.Сортировать()
    │
    ├─► Для каждого потока:
    │       ФоновыеЗадания.Выполнить()
    │           │
    │           └─► VTB_ОбщийМодуль.ВыполнитьИсполнениеСделокПоСпискуДоговорДУ()
    │                   │
    │                   ├─► БизнесПроцессы.СделкиTn.ИсполнениеПлановойПозиции()
    │                   │
    │                   └─► АвтоматическиВыполнитьЗадачиПоСделкеРЕПО()
    │
    └─► Если ПроверкаВыполнения:
            Пока все задания не завершены:
                ФоновыеЗадания.НайтиПоУникальномуИдентификатору()
                ТекущееЗадание.ПолучитьСообщенияПользователю()
```

## Ключевые моменты

1. **Распределение происходит по договорам ДУ**, а не по отдельным задачам
2. **Каждый поток получает список договоров** для обработки
3. **Фоновые задания выполняются параллельно** (асинхронно)
4. **Ожидание завершения** происходит в цикле с проверкой состояния
5. **Ошибки собираются** из сообщений завершенных заданий
6. **Алгоритм Bin Packing** обеспечивает равномерное распределение нагрузки
