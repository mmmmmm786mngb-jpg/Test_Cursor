# План оптимизации распределения задач по потокам с динамическим управлением

## Структура изменений

### Новые процедуры и функции:

1. **ВычислитьСреднийВесДоговоров(СписокЗадач)** - Функция
   - Вычисляет целевой вес потока на основе медианы нижних 90% договоров

2. **ЗапуститьПоток(СтруктураПотоков, ИндексПотока)** - Процедура
   - Запускает один поток из очереди

3. **ОбработатьЗавершенныйПоток(Задание, СтруктураПотоков, МассивСообщенийИзЗадания)** - Процедура
   - Обрабатывает завершенный поток и собирает сообщения об ошибках

4. **ПринятьРешениеОКоличествеПотоков(СтруктураПотоков, БазовоеКоличество)** - Процедура
   - Принимает решение об изменении количества одновременно работающих потоков

### Изменяемые процедуры и функции:

1. **РаспределитьЗадачиПоПотокам(ДатаИсполнения, ЧислоПотоков, Пул = Неопределено)** - Функция
   - **Параметры:** БЕЗ ИЗМЕНЕНИЙ (сохраняются все текущие параметры)
   - **Возвращаемое значение:** ТаблицаЗначений (структура та же, но алгоритм распределения изменен)
   - **Изменения:** Новый алгоритм распределения на основе среднего веса

2. **ВыполнитьСделкиВПотоках(ПроверкаВыполнения = Истина, Отказ = Ложь, Комментарий = "", Пул = Неопределено)** - Процедура
   - **Параметры:** БЕЗ ИЗМЕНЕНИЙ (сохраняются все текущие параметры)
   - **Изменения:** Динамическое управление запуском потоков вместо одновременного запуска всех

3. **ОпределитьНаименееЗагруженныйПоток(Потоки)** - Функция
   - **Статус:** УДАЛЯЕТСЯ (больше не используется в новом алгоритме)

### Важные замечания:

- Все текущие параметры процедур сохраняются без изменений
- Используется `ТекущаяДатаСеанса()` вместо устаревшего `ТекущаяДата()`
- Для хранения фоновых заданий используется `Соответствие` (ключ - индекс потока, значение - ссылка на задание)
- Пауза в цикле ожидания динамическая (от 0.1 до текущего значения)

---

## Цель

Изменить принцип создания потоков и их запуска:
- **Текущий подход:** N потоков, все запускаются одновременно, ждут завершения самого долгого
- **Новый подход:** Много потоков (60+), динамическое управление количеством одновременно работающих (N до 2*N), адаптация на основе скорости выполнения

## Основные изменения

### 1. Расчет среднего веса договоров

**Файл:** `ObjectModule_ExternalProcessor.bsl`

**Новая функция:** `ВычислитьСреднийВесДоговоров(СписокЗадач)`

**Параметры:**
- `СписокЗадач` - ТаблицаЗначений с колонками: `КоличествоЗадач`, `ДоговорДУ`

**Возвращаемое значение:**
- Число - целевой вес потока

**Алгоритм (Вариант 10 - Медиана нижних 90% * 2):**

```bsl
Функция ВычислитьСреднийВесДоговоров(СписокЗадач) Экспорт
	
	Если СписокЗадач.Количество() = 0 Тогда
		Возврат 0;
	КонецЕсли;
	
	// 1. Собираем веса в таблицу значений — гарантирует правильную числовую сортировку
	ТЗ = Новый ТаблицаЗначений;
	ТЗ.Колонки.Добавить("Вес", Новый ОписаниеТипов("Число"));
	
	Для Каждого Задача Из СписокЗадач Цикл
		ТЗ.Добавить().Вес = Задача.КоличествоЗадач;
	КонецЦикла;
	
	// 2. Сортируем по возрастанию — теперь точно как числа!
	ТЗ.Сортировать("Вес Возр");
	
	// 3. Определяем границу нижних 90% (отбрасываем верхние 10%)
	Всего = ТЗ.Количество();
	Граница = Макс(1, Цел(Всего * 0.9)); // не меньше 1
	
	// 4. Медиана из нижних 90%
	Колво = Граница;
	Если Колво % 2 = 1 Тогда
		Медиана = ТЗ[Цел(Колво / 2)].Вес;
	Иначе
		Инд1 = Колво / 2 - 1;
		Инд2 = Колво / 2;
		Медиана = (ТЗ[Инд1].Вес + ТЗ[Инд2].Вес) / 2;
	КонецЕсли;
	
	// 5. Целевой вес = медиана × 2
	Возврат Медиана * 2;
	
КонецФункции
```

**Пример:**
- Веса: 500, 300, 200, 150, 100, 100, 100, 100, 90, 90, 80, 50, 50, 30, 20, 10, 10, 5
- Нижние 90%: 5, 10, 10, 20, 30, 50, 50, 80, 90, 90, 100, 100, 100, 100, 150, 200
- Медиана: (80 + 90) / 2 = 85
- Средний вес = 85 * 2 = **170**

### 2. Новый алгоритм распределения задач по потокам

**Файл:** `ObjectModule_ExternalProcessor.bsl`

**Функция:** `РаспределитьЗадачиПоПотокам(ДатаИсполнения, ЧислоПотоков, Пул = Неопределено)` - полная переработка

**Параметры:** БЕЗ ИЗМЕНЕНИЙ (сохраняются все текущие параметры)

**Возвращаемое значение:** ТаблицаЗначений (структура та же: НомерПотока, ТекущаяЗагрузка, МассивДоговоров)

**Новый алгоритм (код 1С 8.3.25):**

```bsl
Функция РаспределитьЗадачиПоПотокам(ДатаИсполнения, ЧислоПотоков, Пул = Неопределено) Экспорт
	
	// 1. Получить список задач (как сейчас, через запрос)
	Запрос = Новый Запрос;
	Запрос.Текст = "ВЫБРАТЬ
		|	КОЛИЧЕСТВО(РАЗЛИЧНЫЕ ВнебиржеваяСделка.Ссылка) КАК КоличествоЗадач,
		|	ВнебиржеваяСделка.БизнесПроцесс.ДоговорДУ КАК ДоговорДУ
		|ИЗ
		|	Задача.ВнебиржеваяСделка КАК ВнебиржеваяСделка
		|ГДЕ
		|	НЕ ВнебиржеваяСделка.ПометкаУдаления
		|	И НЕ ВнебиржеваяСделка.БизнесПроцесс.ПометкаУдаления
		|	И ВнебиржеваяСделка.БизнесПроцесс.АвтоматическоеВыполнениеЗадач
		|	И НЕ ВнебиржеваяСделка.Выполнена
		|	И ВнебиржеваяСделка.СрокИсполнения МЕЖДУ &ДатаНачала И &ДатаОкончания
		|	И (ВнебиржеваяСделка.БизнесПроцесс ССЫЛКА БизнесПроцесс.СделкиTn
		|			ИЛИ ВнебиржеваяСделка.БизнесПроцесс ССЫЛКА БизнесПроцесс.СделкиРЕПО)
		|	И ВЫБОР
		|			КОГДА &РежимЗагрузки = 1
		|				ТОГДА ВнебиржеваяСделка.БизнесПроцесс.ДоговорДУ.ТипКлиентаДУ = ЗНАЧЕНИЕ(Перечисление.ТипыКлиентовДУ.ФизическиеЛица)
		|			КОГДА &РежимЗагрузки = 2
		|				ТОГДА НЕ ВнебиржеваяСделка.БизнесПроцесс.ДоговорДУ.ТипКлиентаДУ = ЗНАЧЕНИЕ(Перечисление.ТипыКлиентовДУ.ФизическиеЛица)
		|			ИНАЧЕ ИСТИНА
		|		КОНЕЦ
		|	И ВЫБОР
		|			КОГДА ВнебиржеваяСделка.БизнесПроцесс ССЫЛКА БизнесПроцесс.СделкиTn
		|				ТОГДА 1 = 1 
		|			КОГДА ВнебиржеваяСделка.БизнесПроцесс ССЫЛКА БизнесПроцесс.СделкиРЕПО
		|				ТОГДА 1 = 1
		|			ИНАЧЕ ИСТИНА
		|		КОНЕЦ
		|
		|СГРУППИРОВАТЬ ПО
		|	ВнебиржеваяСделка.БизнесПроцесс.ДоговорДУ
		|
		|УПОРЯДОЧИТЬ ПО
		|	КОЛИЧЕСТВО(РАЗЛИЧНЫЕ ВнебиржеваяСделка.Ссылка) УБЫВ";
	
	Запрос.УстановитьПараметр("РежимЗагрузки", РежимЗагрузки);
	Запрос.УстановитьПараметр("ДатаНачала", НачалоДня(ДатаИсполнения));
	Запрос.УстановитьПараметр("ДатаОкончания", КонецДня(ДатаИсполнения));
	Если ЗначениеЗаполнено(Пул) Тогда
		Запрос.Текст = СтрЗаменить(Запрос.Текст, "1 = 1", "ВнебиржеваяСделка.БизнесПроцесс.ДоговорДУ.Пул В (&Пул)");
		Запрос.УстановитьПараметр("Пул", Пул);
	Иначе
		Запрос.Текст = СтрЗаменить(Запрос.Текст, "1 = 1", "ВнебиржеваяСделка.БизнесПроцесс.ДоговорДУ.Пул = ЗНАЧЕНИЕ(Справочник.Пул.ПустаяССылка)");
	КонецЕсли;
	
	СписокЗадач = Запрос.Выполнить().Выгрузить();
	
	// Создать структуру для потоков (один раз в начале функции)
	Потоки = Новый ТаблицаЗначений;
	Потоки.Колонки.Добавить("НомерПотока", Новый ОписаниеТипов("Число"));
	Потоки.Колонки.Добавить("ТекущаяЗагрузка", Новый ОписаниеТипов("Число"));
	Потоки.Колонки.Добавить("МассивДоговоров", Новый ОписаниеТипов("Массив"));
	
	Если СписокЗадач.Количество() = 0 Тогда
		// Нет задач - возвращаем пустую таблицу потоков
		Возврат Потоки;
	КонецЕсли;
	
	// 2. Вычислить средний вес
	СреднийВес = ВычислитьСреднийВесДоговоров(СписокЗадач);
	
	// 4. Распределение договоров
	НомерПотока = 0;
	ТекущийПоток = Потоки.Добавить();
	ТекущийПоток.НомерПотока = НомерПотока;
	ТекущийПоток.ТекущаяЗагрузка = 0;
	ТекущийПоток.МассивДоговоров = Новый Массив;
	
	Для Каждого СтрокаЗадачи Из СписокЗадач Цикл
		
		ВесДоговора = СтрокаЗадачи.КоличествоЗадач;
		
		Если ВесДоговора >= СреднийВес Тогда
			// Большой договор - один в поток
			Если ТекущийПоток.МассивДоговоров.Количество() > 0 Тогда
				// Если текущий поток не пустой - создать новый
				НомерПотока = НомерПотока + 1;
				ТекущийПоток = Потоки.Добавить();
				ТекущийПоток.НомерПотока = НомерПотока;
				ТекущийПоток.ТекущаяЗагрузка = 0;
				ТекущийПоток.МассивДоговоров = Новый Массив;
			КонецЕсли;
			
			ТекущийПоток.МассивДоговоров.Добавить(СтрокаЗадачи.ДоговорДУ);
			ТекущийПоток.ТекущаяЗагрузка = ВесДоговора;
			
			// Создать следующий поток для следующих договоров
			НомерПотока = НомерПотока + 1;
			ТекущийПоток = Потоки.Добавить();
			ТекущийПоток.НомерПотока = НомерПотока;
			ТекущийПоток.ТекущаяЗагрузка = 0;
			ТекущийПоток.МассивДоговоров = Новый Массив;
			
		Иначе
			// Малый договор - пытаемся добавить к текущему потоку
			Если ТекущийПоток.ТекущаяЗагрузка + ВесДоговора <= СреднийВес Тогда
				// Влезает в текущий поток
				ТекущийПоток.МассивДоговоров.Добавить(СтрокаЗадачи.ДоговорДУ);
				ТекущийПоток.ТекущаяЗагрузка = ТекущийПоток.ТекущаяЗагрузка + ВесДоговора;
			Иначе
				// Текущий поток заполнен, создаем новый
				НомерПотока = НомерПотока + 1;
				ТекущийПоток = Потоки.Добавить();
				ТекущийПоток.НомерПотока = НомерПотока;
				ТекущийПоток.ТекущаяЗагрузка = ВесДоговора;
				ТекущийПоток.МассивДоговоров = Новый Массив;
				ТекущийПоток.МассивДоговоров.Добавить(СтрокаЗадачи.ДоговорДУ);
			КонецЕсли;
		КонецЕсли;
		
	КонецЦикла;
	
	// 5. Обработка хвостиков
	// Если последний поток пустой - удалить его
	Если ТекущийПоток.МассивДоговоров.Количество() = 0 Тогда
		ИндексПоследнейСтроки = Потоки.Количество() - 1;
		Потоки.Удалить(ИндексПоследнейСтроки);
	КонецЕсли;
	
	Возврат Потоки;
	
КонецФункции
```

**Результат:** Таблица значений "Потоки" с количеством строк, равным количеству созданных потоков (может быть 60+)

### 3. Динамическое управление запуском потоков

**Файл:** `ObjectModule_ExternalProcessor.bsl`

**Процедура:** `ВыполнитьСделкиВПотоках(ПроверкаВыполнения = Истина, Отказ = Ложь, Комментарий = "", Пул = Неопределено)` - полная переработка

**Параметры:** БЕЗ ИЗМЕНЕНИЙ (сохраняются все текущие параметры)

**Новая структура данных для отслеживания:**

```bsl
// Структура для управления потоками
СтруктураПотоков = Новый Структура;
СтруктураПотоков.Вставить("ВсеПотоки", Потоки); // Все созданные потоки (ТаблицаЗначений)
СтруктураПотоков.Вставить("АктивныеЗадания", Новый Соответствие); // Ключ: ИндексПотока (Число), Значение: ФоновоеЗадание (ссылка)
СтруктураПотоков.Вставить("ИндексСледующегоПотока", 0); // Индекс следующего потока для запуска
СтруктураПотоков.Вставить("ЦелевоеКоличествоАктивных", КоличествоПотоков); // Целевое количество (N до 2*N)
СтруктураПотоков.Вставить("ВремяНачалаПериода", ТекущаяДатаСеанса()); // Для расчета скорости
СтруктураПотоков.Вставить("КоличествоЗавершенныхВПериод", 0); // Количество завершенных за последний период
СтруктураПотоков.Вставить("ПредыдущееКоличествоЗавершенных", 0); // Для сравнения скорости
СтруктураПотоков.Вставить("ТекущаяПауза", 1.0); // Динамическая пауза (от 0.1 до текущего значения)
```

**Алгоритм запуска (код 1С 8.3.25):**

```bsl
Процедура ВыполнитьСделкиВПотоках(ПроверкаВыполнения = Истина, Отказ = Ложь, Комментарий = "", Пул = Неопределено) Экспорт
	
	ПараметрыЗадания = Новый Структура;
	ПараметрыЗадания.Вставить("ДатаИсполнения", ДатаИсполнения);
	
	// 1. Создать все потоки заранее
	Потоки = РаспределитьЗадачиПоПотокам(ДатаИсполнения, КоличествоПотоков, Пул);
	// Потоков может быть 60+
	
	Если Потоки.Количество() = 0 Тогда
		Комментарий = Комментарий + Символы.ПС + "Нет задач для выполнения";
		Возврат;
	КонецЕсли;
	
	// 2. Создать структуру для управления потоками
	СтруктураПотоков = Новый Структура;
	СтруктураПотоков.Вставить("ВсеПотоки", Потоки);
	СтруктураПотоков.Вставить("АктивныеЗадания", Новый Соответствие); // Ключ: ИндексПотока, Значение: ФоновоеЗадание
	СтруктураПотоков.Вставить("ИндексСледующегоПотока", 0);
	СтруктураПотоков.Вставить("ЦелевоеКоличествоАктивных", КоличествоПотоков); // Начальное = N
	СтруктураПотоков.Вставить("ВремяНачалаПериода", ТекущаяДатаСеанса());
	СтруктураПотоков.Вставить("КоличествоЗавершенныхВПериод", 0);
	СтруктураПотоков.Вставить("ПредыдущееКоличествоЗавершенных", 0);
	СтруктураПотоков.Вставить("ТекущаяПауза", 1.0); // Начальная пауза = 1 секунда
	
	МассивСообщенийИзЗадания = Новый Массив;
	
	// 3. Начальный запуск N потоков
	Для Сч = 0 По КоличествоПотоков - 1 Цикл
		Если Сч >= Потоки.Количество() Тогда
			Прервать; // Если потоков меньше чем N
		КонецЕсли;
		ЗапуститьПоток(СтруктураПотоков, Сч, ПараметрыЗадания, МассивСообщенийИзЗадания);
	КонецЦикла;
	
	// 4. Цикл ожидания с динамическим управлением
	Если ПроверкаВыполнения Тогда
		
		Пока СтруктураПотоков.ИндексСледующегоПотока < Потоки.Количество() 
		      Или СтруктураПотоков.АктивныеЗадания.Количество() > 0 Цикл
			
			// Проверка состояния активных потоков
			МассивЗавершенныхИндексов = Новый Массив;
			
			Для Каждого ЭлементСоответствия Из СтруктураПотоков.АктивныеЗадания Цикл
				
				ИндексПотока = ЭлементСоответствия.Ключ;
				Задание = ЭлементСоответствия.Значение;
				
				Если Задание.Состояние <> СостояниеФоновогоЗадания.Активно Тогда
					// Поток завершен
					МассивЗавершенныхИндексов.Добавить(ИндексПотока);
					ОбработатьЗавершенныйПоток(Задание, СтруктураПотоков, МассивСообщенийИзЗадания);
				КонецЕсли;
				
			КонецЦикла;
			
			// Удалить завершенные из активных
			Для Каждого ИндексПотока Из МассивЗавершенныхИндексов Цикл
				СтруктураПотоков.АктивныеЗадания.Удалить(ИндексПотока);
			КонецЦикла;
			
			// В КОНЦЕ ЦИКЛА: Принять решение о количестве одновременно работающих
			ПринятьРешениеОКоличествеПотоков(СтруктураПотоков, КоличествоПотоков);
			
			// Запустить новые потоки, если есть свободные слоты
			Пока СтруктураПотоков.АктивныеЗадания.Количество() < СтруктураПотоков.ЦелевоеКоличествоАктивных 
			      И СтруктураПотоков.ИндексСледующегоПотока < Потоки.Количество() Цикл
				
				ЗапуститьПоток(СтруктураПотоков, СтруктураПотоков.ИндексСледующегоПотока, ПараметрыЗадания, МассивСообщенийИзЗадания);
				СтруктураПотоков.ИндексСледующегоПотока = СтруктураПотоков.ИндексСледующегоПотока + 1;
				
			КонецЦикла;
```

### 4. Функция принятия решения о количестве потоков

**Файл:** `ObjectModule_ExternalProcessor.bsl`

**Параметры:**
- `СтруктураПотоков` - Структура (изменяется внутри функции)
- `БазовоеКоличество` - Число (N - базовое количество потоков)

**Алгоритм (код 1С 8.3.25):**

```bsl
Процедура ПринятьРешениеОКоличествеПотоков(СтруктураПотоков, БазовоеКоличество)
	
	ТекущееВремя = ТекущаяДатаСеанса();
	ПрошлоВремени = ТекущееВремя - СтруктураПотоков.ВремяНачалаПериода;
	
	// Период проверки = 5 секунд
	Если ПрошлоВремени >= 5 Тогда
		
		СкоростьТекущая = СтруктураПотоков.КоличествоЗавершенныхВПериод;
		СкоростьПредыдущая = СтруктураПотоков.ПредыдущееКоличествоЗавершенных;
		
		// Сравнение скорости
		Если СкоростьТекущая > СкоростьПредыдущая Тогда
			// Скорость растет - можно увеличить количество потоков
			Если СтруктураПотоков.ЦелевоеКоличествоАктивных < БазовоеКоличество * 2 Тогда
				СтруктураПотоков.ЦелевоеКоличествоАктивных = СтруктураПотоков.ЦелевоеКоличествоАктивных + 1;
				// Уменьшаем паузу при росте скорости
				СтруктураПотоков.ТекущаяПауза = Макс(0.1, СтруктураПотоков.ТекущаяПауза - 0.1);
			КонецЕсли;
		ИначеЕсли СкоростьТекущая < СкоростьПредыдущая Тогда
			// Скорость падает - уменьшаем количество потоков
			Если СтруктураПотоков.ЦелевоеКоличествоАктивных > БазовоеКоличество Тогда
				СтруктураПотоков.ЦелевоеКоличествоАктивных = СтруктураПотоков.ЦелевоеКоличествоАктивных - 1;
				// Увеличиваем паузу при падении скорости
				СтруктураПотоков.ТекущаяПауза = Мин(1.0, СтруктураПотоков.ТекущаяПауза + 0.1);
			КонецЕсли;
		КонецЕсли;
		
		// Обновить данные для следующего периода
		СтруктураПотоков.ПредыдущееКоличествоЗавершенных = СкоростьТекущая;
		СтруктураПотоков.КоличествоЗавершенныхВПериод = 0;
		СтруктураПотоков.ВремяНачалаПериода = ТекущееВремя;
		
	КонецЕсли;
	
	// Ограничения (на всякий случай)
	Если СтруктураПотоков.ЦелевоеКоличествоАктивных < БазовоеКоличество Тогда
		СтруктураПотоков.ЦелевоеКоличествоАктивных = БазовоеКоличество;
	ИначеЕсли СтруктураПотоков.ЦелевоеКоличествоАктивных > БазовоеКоличество * 2 Тогда
		СтруктураПотоков.ЦелевоеКоличествоАктивных = БазовоеКоличество * 2;
	КонецЕсли;
	
КонецПроцедуры
```

**Ограничения:**
- Минимум: `БазовоеКоличество` (N)
- Максимум: `БазовоеКоличество * 2` (2*N)
- Пауза: от 0.1 до 1.0 секунды (динамически изменяется)

## Ключевые моменты реализации

1. **Обработка хвостиков:** После основного распределения проверить, остались ли мелкие договора. Если да - объединить их в дополнительные потоки, даже если суммарный вес меньше среднего.

2. **Динамическое управление:** Решения принимаются в конце каждого цикла проверки состояния. Сравнивается количество завершенных потоков за последний период (5 секунд) с предыдущим периодом.

3. **Ограничения:** Количество одновременно работающих потоков всегда в диапазоне от N до 2*N.

4. **Начальное значение:** При старте запускается N потоков (минимум).

5. **Адаптация:** Если скорость растет - увеличиваем количество (до 2*N), если падает - уменьшаем (до N).

6. **Хранение ссылок:** Используется `Соответствие` для хранения ссылок на фоновые задания (ключ: ИндексПотока, значение: ФоновоеЗадание). Это избавляет от необходимости каждый раз искать задание по УИД.

7. **Динамическая пауза:** Пауза в цикле ожидания изменяется от 0.1 до 1.0 секунды в зависимости от скорости выполнения потоков.

8. **Использование ТекущаяДатаСеанса():** Во всех новых функциях и изменяемых функциях используется `ТекущаяДатаСеанса()` вместо устаревшего `ТекущаяДата()`.

9. **Сохранение параметров:** Все текущие параметры процедур и функций сохраняются без изменений для обратной совместимости.
