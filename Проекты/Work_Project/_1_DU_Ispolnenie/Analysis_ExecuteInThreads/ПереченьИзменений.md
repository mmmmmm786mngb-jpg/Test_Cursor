# Перечень новых и измененных процедур и функций в модуле ObjectModule_Optimiz_v1.bsl

## Новые функции и процедуры

### 1. Функция `ВычислитьСреднийВесДоговоров(СписокЗадач)` - Экспорт

**Расположение:** Строки 751-785

**Назначение:** Вычисляет целевой вес потока на основе медианы нижних 90% договоров (исключая верхние 10% больших договоров).

**Параметры:**

- `СписокЗадач` - ТаблицаЗначений с колонками: `КоличествоЗадач`, `ДоговорДУ`

**Возвращаемое значение:**

- Число - целевой вес потока (медиана нижних 90% * 2)

**Алгоритм:**

1. Собирает веса в таблицу значений
2. Сортирует по возрастанию
3. Определяет границу нижних 90% (отбрасывает верхние 10%)
4. Вычисляет медиану из нижних 90%
5. Возвращает медиану * 2

### 2. Процедура `ЗапуститьПоток(СтруктураПотоков, ИндексПотока, ПараметрыЗадания, МассивСообщенийИзЗадания)`

**Расположение:** Строки 380-411

**Назначение:** Запускает один поток из очереди и сохраняет ссылку на фоновое задание в Соответствии.

**Параметры:**

- `СтруктураПотоков` - Структура (изменяется внутри функции)
- `ИндексПотока` - Число (индекс потока в таблице)
- `ПараметрыЗадания` - Структура (параметры для фонового задания)
- `МассивСообщенийИзЗадания` - Массив (для сбора сообщений об ошибках)

**Особенности:**

- Создает фоновое задание через `ФоновыеЗадания.Выполнить()`
- Сохраняет ссылку на задание в `СтруктураПотоков.АктивныеЗадания` (ключ: ИндексПотока, значение: ФоновоеЗадание)
- Это избавляет от необходимости каждый раз искать задание по УИД

---

### 3. Процедура `ОбработатьЗавершенныйПоток(Задание, СтруктураПотоков, МассивСообщенийИзЗадания)`

**Расположение:** Строки 420-436

**Назначение:** Обрабатывает завершенный поток и собирает сообщения об ошибках.

**Параметры:**

- `Задание` - ФоновоеЗадание (ссылка на завершенное задание)
- `СтруктураПотоков` - Структура (изменяется внутри функции)
- `МассивСообщенийИзЗадания` - Массив (для сбора сообщений об ошибках)

**Особенности:**

- Увеличивает счетчик завершенных потоков в периоде
- Собирает сообщения об ошибках из задания (фильтрует по "Причина отказа")

---

### 4. Процедура `ПринятьРешениеОКоличествеПотоков(СтруктураПотоков, БазовоеКоличество)`

**Расположение:** Строки 444-486

**Назначение:** Принимает решение об изменении количества одновременно работающих потоков на основе скорости выполнения.

**Параметры:**

- `СтруктураПотоков` - Структура (изменяется внутри функции)
- `БазовоеКоличество` - Число (N - базовое количество потоков)

**Алгоритм:**

1. Измеряет время с начала периода (период проверки = 5 секунд)
2. Сравнивает количество завершенных потоков за текущий период с предыдущим
3. Если скорость растет → увеличивает количество одновременно работающих (до 2*N) и уменьшает паузу
4. Если скорость падает → уменьшает количество одновременно работающих (до N) и увеличивает паузу
5. Ограничения: минимум = N, максимум = 2*N

**Особенности:**

- Использует `ТекущаяДатаСеанса()` для измерения времени
- Динамически изменяет паузу (от 0.1 до 1.0 секунды)

## Измененные функции и процедуры

### 1. Функция `РаспределитьЗадачиПоПотокам(ДатаИсполнения, ЧислоПотоков, Пул = Неопределено)` - Экспорт

**Расположение:** Строки 794-918

**Параметры:** БЕЗ ИЗМЕНЕНИЙ (сохраняются все текущие параметры)

**Возвращаемое значение:** ТаблицаЗначений (структура та же: НомерПотока, ТекущаяЗагрузка, МассивДоговоров)

**Основные изменения:**

1. **УДАЛЕНО:** Использование функции `ОпределитьНаименееЗагруженныйПоток` (старый алгоритм Bin Packing)

2. **ДОБАВЛЕНО:** Вызов функции `ВычислитьСреднийВесДоговоров()` для расчета целевого веса потока

3. **ИЗМЕНЕНО:** Алгоритм распределения:
   - Если вес договора >= среднего веса → один договор в поток
   - Если вес договора < среднего веса → объединяет несколько договоров до достижения среднего веса
   - Обработка хвостиков: мелкие договора в конце объединяются в дополнительные потоки

4. **ИЗМЕНЕНО:** Создание таблицы потоков один раз в начале функции (не несколько раз)

**Результат:** Количество созданных потоков может быть 60+ (не ограничено N)

### 2. Процедура `ВыполнитьСделкиВПотоках(ПроверкаВыполнения = Истина, Отказ = Ложь, Комментарий = "", Пул = Неопределено)` - Экспорт

**Расположение:** Строки 280-371

**Параметры:** БЕЗ ИЗМЕНЕНИЙ (сохраняются все текущие параметры)

**Основные изменения:**

1. **УДАЛЕНО:** Одновременный запуск всех N потоков в начале

2. **УДАЛЕНО:** Использование `МассивЗаданий` с УИД для поиска заданий через `ФоновыеЗадания.НайтиПоУникальномуИдентификатору()`

3. **ДОБАВЛЕНО:** Использование `Соответствия` для хранения ссылок на фоновые задания:
   - Ключ: ИндексПотока (Число)
   - Значение: ФоновоеЗадание (ссылка)
   - Это избавляет от необходимости каждый раз искать задание по УИД

4. **ДОБАВЛЕНО:** Динамическое управление количеством одновременно работающих потоков:
   - Начальное количество = N (минимум)
   - Максимальное количество = 2*N
   - Адаптация на основе скорости выполнения

5. **ДОБАВЛЕНО:** Структура для управления потоками:
   - `ВсеПотоки` - ТаблицаЗначений (все созданные потоки)
   - `АктивныеЗадания` - Соответствие (активные фоновые задания)
   - `ИндексСледующегоПотока` - индекс следующего потока для запуска
   - `ЦелевоеКоличествоАктивных` - целевое количество одновременно работающих (N до 2*N)
   - `ВремяНачалаПериода` - для расчета скорости
   - `КоличествоЗавершенныхВПериод` - количество завершенных за период
   - `ПредыдущееКоличествоЗавершенных` - для сравнения скорости
   - `ТекущаяПауза` - динамическая пауза (от 0.1 до 1.0 секунды)

6. **ИЗМЕНЕНО:** Цикл ожидания:
   - Проверка состояния активных потоков через Соответствие
   - В конце каждого цикла: принятие решения о количестве одновременно работающих
   - Запуск новых потоков при освобождении слотов
   - Динамическая пауза (от 0.1 до 1.0 секунды)

7. **ИЗМЕНЕНО:** Использование `ТекущаяДатаСеанса()` вместо `ТекущаяДата()` для измерения времени в цикле

**Результат:** Динамическое управление потоками с адаптацией на основе скорости выполнения
