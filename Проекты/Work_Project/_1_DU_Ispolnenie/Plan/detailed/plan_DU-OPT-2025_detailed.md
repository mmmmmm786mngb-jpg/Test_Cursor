## Этап 1: Подготовка инфраструктуры тестирования

### Сроки
- **Начало:** 27.11.2025 (четверг)
- **Окончание:** 01.12.2025 (понедельник)
- **Длительность:** 3 рабочих дня (15 часов)
- **Дата сдачи этапа:** 01 декабря

### Цель
Полностью рабочий генератор и регламент для запуска исполнений за любой исторический период.

### Планируемые действия

#### 1.1 Создание обработки-генератора
- Название: «Перезапуск исполнений за период»
- Параметры:
  - Дата начала периода
  - Дата окончания периода
  - Типы сделок (фильтр)
  - Клиенты (фильтр)
- Функционал:
  - Выборка сделок по параметрам
  - Формирование очереди на исполнение
  - Логирование процесса

#### 1.2 Доработка регламентного задания
- Задание: «Исполнение сделок»
- Добавление параметров:
  - Принудительный запуск за произвольный период
  - Режим тестирования (без реального проведения)
  - Параметры фильтрации

#### 1.3 Проверка на тестовом контуре
- Объём: 100 000 клиентов
- Верификация работоспособности генератора
- Проверка корректности выборки данных

## Этап 2: Baseline-замеры текущей производительности

### Сроки
- **Начало:** 01.12.2025 (понедельник)
- **Окончание:** 01.12.2025 (понедельник)
- **Длительность:** 1 рабочий день (5 часов)
- **Дата сдачи этапа:** 01 декабря

### Цель
Зафиксированы точные цифры «до» оптимизации.

### Планируемые действия

#### 2.1 Прогоны генератора
- Несколько прогонов
- Период: один и тот же для сопоставимости
- Фиксация каждого прогона

#### 2.2 Сбор метрик
- Источники:
  - Отладчик
  - Тестовые отчеты
- Метрики:
  - Время выполнения (общее и по этапам)
  - Количество действий
  - Топ долгих запросов
  - Топ прочих долгих мест
  - Сравнение метрик работы в параллельном режиме

#### 2.3 Анализ запросов
- Топ долгих запросов
- План выполнения каждого запроса
- Использование индексов
- Количество прочитанных записей

## Этап 3: BA-анализ узких мест

### Сроки
- **Начало:** 02.12.2025 (вторник)
- **Окончание:** 04.12.2025 (четверг)
- **Длительность:** 3 рабочих дня (15 часов)
- **Дата сдачи этапа:** 04 декабря

### Цель
Чёткий приоритизированный список оптимизаций.

### Планируемые действия

#### 3.1 Анализ параллельности
- Анализ параллельности способов изменения режима распределения потоков
- Возможности:
  - Где можно распараллелить?
  - Какие операции независимы?
  - Оценка потенциального ускорения

#### 3.2 Глубокий разбор запросов
- Анализ топ-запросов:
  - Возможность выноса во временные таблицы
  - Необходимые индексы
  - Параметризация запросов

#### 3.3 Документирование «горячих» мест
- Фиксация всех проблемных участков
- Приоритизация по влиянию на производительность
- Оценка трудозатрат на исправление

### Результат этапа
Документ с приоритизированным списком оптимизаций:
1. Критические (блокирующие)
2. Высокий приоритет
3. Средний приоритет
4. Низкий приоритет (nice-to-have)

## Этап 4: Разработка и тестирование оптимизаций

### Сроки
- **Начало:** 05.12.2025 (пятница)
- **Окончание:** 10.12.2025 (среда)
- **Длительность:** 4 рабочих дня (20 часов)
- **Дата сдачи этапа:** 10 декабря

### Цель
Все три блока оптимизаций реализованы и протестированы.

### Планируемые действия

#### 4.1 Реализация управляемой параллельности
- Технологии:
  - Фоновые задания
  - Очереди обработки
  - Разделение по типам сделок
- Реализация:
  - Диспетчер заданий
  - Контроль нагрузки
  - Обработка ошибок

#### 4.2 Переписывание тяжёлых запросов
- Оптимизации:
  - Временные таблицы
  - Новые индексы
  - Пакетная обработка
- Для каждого запроса:
  - Замер «до»
  - Оптимизация
  - Замер «после»
  - Документирование

#### 4.3 Доработка остальных выявленных мест
- Регистры: оптимизация записи/чтения
- Алгоритмы: рефакторинг неэффективных участков
- Кэши: внедрение кэширования справочных данных

#### 4.4 Промежуточные прогоны
- После каждой доработки:
  - Прогон генератора
  - Сравнение с baseline
  - Фиксация прироста производительности
