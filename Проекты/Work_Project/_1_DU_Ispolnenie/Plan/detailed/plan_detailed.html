Этап 1: Подготовка инфраструктуры тестирования

Цель: Полностью рабочий генератор и регламент для запуска исполнений за любой исторический период

Планируемые действия:

1.1 Создание обработки-генератора «Перезапуск исполнений за период»

  • Параметры: дата начала, дата окончания, типы сделок, клиенты (фильтр)
  • Функционал: массовый перезапуск исполнений с очисткой предыдущих результатов
  • Логирование всех операций для последующего анализа
  • Защита от случайного запуска в продуктивном контуре

1.2 Доработка регламентного задания «Исполнение сделок»

  • Добавление возможности принудительного запуска за произвольный период
  • Параметризация через XML-файл или внешнюю обработку
  • Сохранение совместимости с текущим режимом работы

1.3 Проверка на тестовом контуре

  • Тестирование на 100 тыс. клиентов
  • Проверка корректности данных после перезапуска
  • Валидация результатов исполнения

Критерии приёмки:

  • Генератор успешно запускает исполнения за любой период в прошлом
  • Результаты идентичны результатам обычного исполнения
  • Все операции логируются и могут быть воспроизведены
  • Нет ошибок при обработке 100 тыс. клиентов

Риски и митигации:

Риск: Несовместимость данных при перезапуске старых периодов
Митигация: Полная очистка зависимых данных перед перезапуском, проверка целостности

Риск: Долгое время выполнения на больших объёмах
Митигация: Оптимизация запросов в генераторе, возможность разбиения на батчи

Метрики успеха:

  • Время создания генератора: ≤ 8 часов
  • Время тестирования на 100К клиентов: ≤ 4 часа
  • Процент успешных перезапусков: 100%

Этап 2: Baseline-замеры текущей производительности

Цель: Зафиксированы точные цифры «до» оптимизации

Планируемые действия:

2.1 Три прогона генератора за один и тот же период

  • Выбор репрезентативного периода (например, последний месяц)
  • Три независимых запуска для исключения случайных факторов
  • Фиксация всех параметров окружения

2.2 Сбор метрик через Центр мониторинга и технологический журнал

  • Время выполнения каждого этапа исполнения
  • Количество обработанных записей
  • Использование CPU, памяти, дискового I/O
  • Количество и длительность блокировок
  • Топ-10 самых долгих запросов с планами выполнения

2.3 Фиксация результатов

  • Сохранение всех метрик в структурированном виде (Excel/JSON)
  • Скриншоты графиков из Центра мониторинга
  • Экспорт технологического журнала для анализа

  • Разброс результатов между прогонами: ≤ 5%

Этап 3: BA-анализ узких мест

Цель: Чёткий приоритизированный список оптимизаций

Планируемые действия:

3.1 Анализ параллельности

  • Изучение текущей архитектуры исполнения сделок
  • Выявление причин последовательного выполнения
  • Определение возможностей распараллеливания:
    • По типам сделок
    • По клиентам
    • По периодам
  • Оценка рисков параллельного выполнения

3.2 Глубокий разбор топ-запросов и СКД

  • Анализ планов выполнения каждого проблемного запроса
  • Поиск возможностей оптимизации:
    • Вынос в временные таблицы
    • Создание/модификация индексов
    • Параметризация запросов
    • Переписывание логики запросов
  • Анализ СКД (системы компоновки данных):
    • Оптимизация настроек компоновки
    • Вынос вычислений из запросов
    • Кэширование результатов

3.3 Выявление остальных «горячих» мест

  • Анализ регистров сведений и накопления
  • Проверка алгоритмов расчётов
  • Изучение механизмов кэширования
  • Анализ работы фоновых заданий
  • Документирование всех найденных проблем

Этап 4: Разработка и тестирование оптимизаций

Цель: Все три блока реализованы и протестированы

Планируемые действия:

4.1 Реализация управляемой параллельности

  • Разработка механизма фоновых заданий / очередей
  • Реализация разделения по типам сделок
  • Добавление контроля параллельности (ограничение количества одновременных задач)
  • Обработка ошибок и откат при сбоях
  • Тестирование на тестовом контуре

4.2 Переписывание тяжёлых запросов

  • Создание временных таблиц для промежуточных результатов
  • Создание/модификация индексов
  • Параметризация запросов
  • Реализация пакетной обработки
  • Тестирование каждого изменённого запроса

4.3 Доработка остальных выявленных мест

  • Оптимизация регистров (индексы, структура)
  • Улучшение алгоритмов расчётов
  • Настройка кэширования
  • Оптимизация работы с данными

4.4 Промежуточные прогоны после каждой доработки

  • Запуск генератора после каждой значимой оптимизации
  • Сравнение результатов с baseline
  • Фиксация достигнутого прироста производительности
  • Корректировка плана при необходимости
