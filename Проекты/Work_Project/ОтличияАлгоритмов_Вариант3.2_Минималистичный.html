Старый алгоритм (до изменений)

Основные характеристики

  • Фиксированное количество потоков: Всегда запускается ровно 6 потоков (или значение из настройки КоличествоПотоков)
  • Статическое распределение: Все договоры распределяются по потокам заранее по принципу "наименее загруженный поток"
  • Одновременный запуск: Все потоки запускаются сразу и висят до завершения
  • Простое ожидание: Фиксированная пауза 5 секунд между проверками состояния

Проблемы

  • Все потоки запускаются одновременно и "висят" до завершения
  • Нет адаптации к скорости выполнения
  • Неэффективное использование ресурсов при неравномерной нагрузке

Новый алгоритм (после изменений)

Основные характеристики

  • Динамическое управление потоками: Количество одновременно работающих потоков изменяется от КоличествоПотоков до 3×КоличествоПотоков в зависимости от скорости выполнения
  • Статистический анализ весов: Расчет целевого веса потока по формуле max(Q1 + 3.0×IQR, Медиана × 2.5, Среднее × 1.75)
  • Умное распределение договоров: Большие договоры — отдельный поток, маленькие объединяются до целевого веса
  • Адаптивная пауза: Динамически изменяется от 0.05 до 2.0 секунд
  • Мониторинг скорости: Каждую минуту корректируется количество активных потоков

Принцип запуска потоков

Старый алгоритм

  1. Распределение: все договоры по КоличествоПотоков потокам заранее
  2. Запуск: все потоки запускаются сразу (по количеству из настройки)
  3. Ожидание: фиксированная пауза 5 секунд
  4. Проблема: все потоки "висят" до завершения

Новый алгоритм

  1. Распределение: все договоры по потокам заранее (таблица потоков)
  2. Первичный запуск: только первые потоки (по количеству из настройки)
  3. Цикл ожидания:
    • Проверка завершенных потоков
    • Адаптация целевого количества (КоличествоПотоков ÷ 3×КоличествоПотоков)
    • Запуск новых потоков по мере освобождения
    • Адаптивная пауза (0.05 ÷ 2.0 сек)

Механизм работы

  • Спринт-старт: При большой очереди сразу запускается 1.8×КоличествоПотоков потоков
  • Адаптивное управление: При росте скорости — увеличение потоков, при падении — уменьшение
  • Динамическая пауза: Автоматически корректируется в зависимости от скорости

Планируемый прирост производительности

  • Ускорение выполнения: планируется ускорение в 1.5 раза по сравнению со старым алгоритмом
  • Сокращение времени: ожидаемое сокращение времени выполнения на 30-35%
  • Эффективность ресурсов: более эффективное использование ресурсов сервера за счет динамического управления потоками
  • Масштабируемость: автоматическая адаптация к изменению нагрузки без ручной настройки
