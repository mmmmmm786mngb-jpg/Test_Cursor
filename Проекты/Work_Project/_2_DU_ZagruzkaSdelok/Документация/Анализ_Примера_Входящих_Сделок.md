## 4. Что будет создано при загрузке

### 4.1. Обычные биржевые сделки (TQBR) - 14 сделок

**Тип создаваемого объекта:** **БизнесПроцесс.СделкиTn**

**Условие создания:**

- Режим торгов = "TQBR"
- `Лев(РежимТоргов, 2) = "TQ"` - **ДА!** (первые 2 символа "TQ")
- ИЛИ `НачалоДня(ДатаСделки) <> НачалоДня(ДатаРасчетов)` - **ДА!** (14.11.2025 <> 17.11.2025)
- НЕ является сделкой РЕПО
- НЕ является сделкой срочного рынка
- НЕ является валютной сделкой

**ВАЖНО:** Для режима торгов "TQBR" всегда создается **БП СделкиTn**, а не Документ.Сделка, потому что:

- Первые 2 символа = "TQ" (условие выполняется)
- ИЛИ даты сделки и расчетов разные (T+3)

**Что будет создано:**

1. **БизнесПроцесс.СделкиTn** с заполненными реквизитами:
   - **НомерСделки** = НомерСделки из внешней системы
   - **Дата** = ДатаСделки (14.11.2025)
   - **ВидОперации** =
     - Перечисления.ВидыОперацийСделка.Продажа (для продаж)
     - Перечисления.ВидыОперацийСделка.Поступление (для покупок)
   - **ДоговорДУ** = определяется по КодКлиента "8U0771/0859"
   - **Актив** = определяется по данным из внешней системы
   - **Количество** = из входящих данных
   - **Цена** = из входящих данных
   - **СуммаДокумента** = Сумма из входящих данных
   - **НКД** = из входящих данных
   - **Контрагент** = определяется по КодБрокера (если заполнен)
   - **ДоговорКонтрагента** = определяется автоматически
   - **ВалютаДокумента** = "SUR" (рубли)
   - **АналитическийСчетЦБ** = определяется по договору ДУ и активу (используется для T+ сделок)
   - **АналитическийСчетДС** = определяется по договору ДУ и валюте
   - **АвтоматическоеВыполнениеЗадач** = Истина
   - **КомиссиюБрокераОтноситьНаРасходыПриОплате** = 2
   - **КомиссиюБиржиОтноситьНаРасходыПриОплате** = 2

2. **Дополнительные расходы (ДопРасходы):**
   - Комиссия биржи (komissija_birga)
   - Комиссия клиринга (komissija_kliring)
   - Комиссия торговой системы (TSCommission)
   - Комиссия брокера (CmsBroker)

3. **Даты:**
   - **ДатаОплатыСделки** = ДатаРасчетов (17.11.2025) + ВремяСделки
   - **ДатаПоставки** = ДатаРасчетов (17.11.2025) + ВремяСделки

4. **Проведение:**
   - Бизнес-процесс будет **проведен сразу** при записи
   - Режим записи: `ТекСделка.Записать(РежимЗаписиДокумента.Проведение)`
   - Задачи будут выполняться автоматически: `АвтоматическоеВыполнениеЗадач = Истина`

### 4.1.1. Какие задачи создаются и что остается невыполненным

**Маршрут БП СделкиTn (упрощенно):**

- `Старт` → `УстановкаНастроекБП` → `ОткрытиеПлановойПозиции` → `Разделение1` →
  - `ОплатаСделки`
  - `ЗакрытиеПлановойПозиции`
  - `ЕстьКомиссияБрокера` → `ОплатаКомиссииБрокера`
  - `ЕстьКомиссияБиржи` → `ОплатаКомиссииБиржи`
  - Все ветки сходятся в `Слияние1` → `Завершение`.

**Что выполняется автоматически при старте БП (для нашего примера):**

- При старте БП и флаге `АвтоматическоеВыполнениеЗадач = Истина`:
  - Для точки `УстановкаНастроекБП` в модуле объекта вызывается `УстановкаНастроекБизнесПроцессаПриСозданииЗадач`:
    - Создается задача `Задачи.ВнебиржеваяСделка.СоздатьЗадачу()`
    - Сразу же выполняется методом `ВыполнитьЗадачу()`
    - Вызывается `БизнесПроцессы.СделкиTn.ПриСозданииЗадач(...)`
  - В результате **задача по установке настроек не остается в списке открытых задач**.

**Какие задачи создаются и остаются невыполненными после старта (для всех 14 TQBR-сделок):**

- **Всегда создаются и ждут выполнения:**
  - `ОткрытиеПлановойПозиции` – открытие плановой позиции по сделке.
  - `ОплатаСделки` – оплата основной суммы сделки на дату `ДатаОплатыСделки` (T+3).
  - `ЗакрытиеПлановойПозиции` – закрытие плановой позиции на дату `ДатаПоставки`.
- **Создаются при наличии соответствующих комиссий:**
  - `ОплатаКомиссииБрокера` – если по сделке рассчитана комиссия брокера (`CmsBroker > 0`).
  - `ОплатаКомиссииБиржи` – если по сделке есть комиссия биржи (`komissija_birga > 0`).

**Как эти задачи добиваются:**

- Регламентная процедура `БизнесПроцессы.СделкиTn.ИсполнениеПлановойПозиции(Дата, Отказ, ТекстОтказа, ...)`:
  - На выбранную дату выбирает открытые задачи по СделкиTn через `ПолучитьОткрытыеЗадачиПоСделкеTn()`.
  - Для каждой задачи:
    - Получает объект задачи `ТекЗадача.Ссылка.ПолучитьОбъект()`.
    - Устанавливает флаг `СинхронизоватьПредметПоЗадаче = Истина`.
    - Вызывает `ВыполнитьЗадачу()`, что, в свою очередь, запускает обработчики `...ПриВыполнении`:
      - `ОплатаСделкиПриВыполнении` – создает и проводит платеж по сделке.
      - `ОплатаКомиссииБрокераПриВыполнении` – проводит платеж комиссии брокера (если есть).
      - `ОплатаКомиссииБиржиПриВыполнении` – проводит платеж комиссии биржи (если есть).
      - `ЗакрытиеПлановойПозицииПриВыполнении` – оформляет закрытие плановой позиции.

### 4.2.1. Задачи маршрута БП СделкиРЕПО для этой сделки

**Маршрут (упрощенно):**
- `Старт` → `УстановкаНастроекБП` →
  - `ПерваяЧастьРЕПО` → `Разделение1`:
    - `ОплатаПервойЧастиСделкиЧерезБрокера`
    - при наличии комиссий:
      - `ОплатаКомиссииБрокераПерваяЧасть`
      - `ОплатаКомиссииБиржиПерваяЧасть`
    - все ветки сходятся в `Слияние1` →
  - `ВтораяЧастьРЕПО` → `Разделение2`:
    - `ОплатаВторойЧастиСделкиЧерезБрокера`
    - при наличии комиссий:
      - `ОплатаКомиссииБрокераВтораяЧасть`
      - `ОплатаКомиссииБиржиВтораяЧасть`
    - все ветки сходятся в `Слияние2` → `Завершение`.

**Что выполняется сразу при старте:**
- При установке флага `АвтоматическоеВыполнениеЗадач = Истина`:
  - в точке `УстановкаНастроекБП` процедура `УстановкаНастроекБизнесПроцессаПриСозданииЗадач`:
    - создает задачу `Задачи.ВнебиржеваяСделка.СоздатьЗадачу()`;
    - сразу выполняет ее (`ВыполнитьЗадачу()`);
    - вызывает `БизнесПроцессы.СделкиРЕПО.ПриСозданииЗадач(...)`.
  - Эта задача **не остается открытой** после старта БП.

**Какие задачи создаются и остаются невыполненными после старта (для сделки 14707529186):**

- По **первой части РЕПО**:
  - `ПерваяЧастьРЕПО` — оформление первой части РЕПО, срок = `ДатаПеререгистрацииПервойЧастиСделкиРЕПО` (14.11.2025).
  - `ОплатаПервойЧастиСделкиЧерезБрокера` — оплата первой части, срок = `ДатаОплатыПервойЧастиСделкиРЕПО` (14.11.2025 + несколько секунд).
  - `ОплатаКомиссииБрокераПерваяЧасть` — создается, если `КомиссияБрокераПервойЧастиРЕПО > 0` (в примере комиссионные брокера по 1-й части есть).
  - `ОплатаКомиссииБиржиПерваяЧасть` — создается, если `КомиссияБиржиПервойЧастиРЕПО > 0` (в примере `КомиссияБиржиПервойЧастиРЕПО = 33.19` > 0).

- По **второй части РЕПО**:
  - `ВтораяЧастьРЕПО` — оформление второй части РЕПО, срок = `ДатаПеререгистрацииВторойЧастиСделкиРЕПО` (17.11.2025).
  - `ОплатаВторойЧастиСделкиЧерезБрокера` — оплата второй части, срок = `ДатаОплатыВторойЧастиСделкиРЕПО` (17.11.2025 + несколько секунд).
  - `ОплатаКомиссииБрокераВтораяЧасть` — создается, если рассчитана комиссия брокера по 2-й части (`КомиссияБрокераВторойЧастиРЕПО > 0`).
  - `ОплатаКомиссииБиржиВтораяЧасть` — создается, если рассчитана комиссия биржи по 2-й части (`КомиссияБиржиВторойЧастиРЕПО > 0`).

**Когда и как эти задачи выполняются:**
- При закрытии дня/периода с операцией **«Исполнение плановой позиции»**:
  - движок выбирает открытые задачи по БП СделкиРЕПО на соответствующие даты;
  - для каждой задачи:
    - получает объект задачи `Задача.Ссылка.ПолучитьОбъект()`;
    - выставляет `СинхронизоватьПредметПоЗадаче = Истина`;
    - вызывает `ВыполнитьЗадачу()`, что запускает соответствующий обработчик `...ПриВыполнении`:
      - оформляется первая/вторая часть РЕПО;
      - оформляется оплата первой/второй части;
      - оформляются оплаты комиссий брокера и биржи.
- При необходимости пользователь может выполнить любую из задач вручную из списка задач.

## 6. Особенности обработки данных

### 6.1. Определение активов

Актив определяется по данным из внешней системы через функцию `АктивПоКоду()`. В примере все активы имеют тип "ЦБ" (ценные бумаги).

### 6.2. Определение брокера

Брокер определяется по полю `КодБрокера`. В примере все поля пустые, поэтому брокер будет определен по другим признакам или не будет заполнен.

### 6.3. Комиссии

Комиссии распределяются следующим образом:

- **Комиссия биржи:** из поля `komissija_birga`
- **Комиссия клиринга:** из поля `komissija_kliring`
- **Комиссия торговой системы:** из поля `TSCommission`
- **Комиссия брокера:** из поля `CmsBroker`

Все комиссии добавляются в табличную часть **ДопРасходы** документа/БП.

### 6.4. Даты расчетов

Для обычных сделок TQBR:

- Дата расчетов = 17.11.2025 (T+3 от даты сделки 14.11.2025)
- Дата оплаты = Дата расчетов + Время сделки

Для РЕПО:

- Дата расчетов первой части = 14.11.2025 (T+0)
- Дата расчетов второй части = 17.11.2025 (T+3)
- Время второй части = 07:20:00 (фиксированное)

## 7. Проверка существования перед созданием

Перед созданием каждой сделки выполняется проверка через `ОтобратьСделкиПоНомеру()`:

1. Проверяется существование сделки с таким же **НомерСделки**
2. Проверяется **ВидОперации** (Покупка/Продажа)
3. Проверяются все типы объектов:
   - Документ.Сделка
   - БизнесПроцесс.СделкиTn
   - БизнесПроцесс.ВнебиржеваяСделка
   - Документ.СделкаНаСрочномРынке
   - БизнесПроцесс.СделкиРЕПО
   - Документ.СделкаНаВалютномРынке

Если сделка уже существует, она **не будет создана повторно**.
