## 1. Общая информация

**Обработка:** `внЗагрузкаСделокDU-NEW`  
**Расположение:** `C:\1c\Cursor_1c\WORK\Wim_Du\SRC\epf\внЗагрузкаСделокDU-NEW`  
**Конфигурация:** `C:\1c\Cursor_1c\WORK\Wim_Du\SRC\CF`

## 2. Источник данных и способ загрузки

### 2.1. Источник данных

**Веб-сервис TIBCO:**

- **Продуктивный:** `http://amaptibco:8889/`
- **Тестовый:** `http://smsk02ap209u:8889/`
- **Пространство имен:** `http://www.avancore.ru/deals`

### 2.2. Способ загрузки

**Технология:** Web Services (WS) через XDTO

**Процесс:**

1. Создание WSОпределения по URL веб-сервиса
2. Формирование XDTO объектов (Корень, Условия)
3. Установка параметров отбора:
   - ДатаС - ДатаНачала
   - ДатаПо - ДатаОкончания
   - База - код брокера (DV_BrokerCode)
   - ОтборOTC - фильтр по внебиржевым сделкам
   - ISIN - список инструментов для отбора
4. Вызов веб-сервиса через `ОтветЧерезСервис()`
5. Получение массива сделок в формате XDTO

**Код подключения:**

```bsl
TIBCO_URL = ?(ТестовыйРежим, "http://smsk02ap209u:8889/", "http://amaptibco:8889/");
Определение = Новый WSОпределения(TIBCO_URL);
Фабрика = Определение.ФабрикаXDTO;
Корень_ТИП = Фабрика.Тип(ОсновноеПространствоИмен, "Корень");
Условия_ТИП = Фабрика.Тип(ОсновноеПространствоИмен, "Условия");
Корень = Фабрика.Создать(Корень_ТИП);
Условия = Фабрика.Создать(Условия_ТИП);
Ответ = ОтветЧерезСервис(Определение, Корень);
```

## 3. Основные этапы загрузки

### 3.1. Этап 1: Загрузка данных из внешней системы

**Метод:** `ЗагрузитьОбъекты(Отказ, ТекстОшибки)`

**Действия:**

1. Подключение к веб-сервису TIBCO
2. Формирование условий отбора
3. Получение сделок за период
4. Парсинг XDTO ответа
5. Вызов `ПрочитатьНаСервере()` для обработки сделок

### 3.2. Этап 2: Обработка и валидация данных

**Метод:** `ПрочитатьНаСервере(Сделки, Отказ)`

**Действия:**

1. Преобразование XDTO сделок в таблицу значений
2. Определение типа сделки (обычная, РЕПО, внебиржевая, срочный рынок, валютная)
3. Проверка существования сделок через `ОтобратьСделкиПоНомеру()`
4. Определение активов, валют, брокеров
5. Заполнение таблицы `СписокЗагрузки` и `СписокЗагрузкиВалютныеСделки`

### 3.3. Этап 3: Создание объектов в базе данных

**Метод:** `СоздатьОбъекты(Отказ, ТекстОшибки)`

**Действия:**

1. Итерация по списку загрузки
2. Определение типа создаваемого объекта
3. Создание документа или бизнес-процесса
4. Заполнение реквизитов
5. Запись и проведение/запуск

## 4. Типы создаваемых документов и бизнес-процессов

### 4.1. Бизнес-процессы

#### 4.1.1. СделкиРЕПО

**Условие создания:** Режим торгов содержит:

- `RP`, `RD`, `RE` (прямое РЕПО)
- `WP`, `WD`, `WE` (обратное РЕПО)
- `PSRY` (РЕПО с ЦК)
- `EQ` + `BND` (комбинация)
- Или функция `ЭтоРЕПО_КСУ()` возвращает Истина

**Характеристики:**

- Создается через `БизнесПроцессы.СделкиРЕПО.СоздатьБизнесПроцесс()`
- Записывается без проведения: `ТекСделка.Записать()`
- Запускается: `ТекСделка.Старт()`
- Автоматическое выполнение задач: `АвтоматическоеВыполнениеЗадач = Истина`

**Ключевые реквизиты:**

- НомерСделки, Дата
- ВидОперации (ПрямойРЕПО/ОбратныйРЕПО)
- ДатаПеререгистрацииПервойЧастиСделкиРЕПО
- ДатаПеререгистрацииВторойЧастиСделкиРЕПО (для прямого РЕПО)
- ДатаОплатыПервойЧастиСделкиРЕПО
- ДатаОплатыВторойЧастиСделкиРЕПО
- СуммаПервойЧастиРЕПО, СуммаВторойЧастиРЕПО
- НКДПервойЧастиСделкиРЕПО, НКДВторойЧастиСделкиРЕПО
- КомиссияБиржиПервойЧастиРЕПО, КомиссияБрокераПервойЧастиРЕПО
- СрокСделки, СтавкаРепо, НачальныйДисконт

**Задачи маршрута и их исполнение:**

- **Маршрут (упрощенно):**
  - `Старт` → `УстановкаНастроекБП` → `ПерваяЧастьРЕПО` → `Разделение1`:
    - `ОплатаПервойЧастиСделкиЧерезБрокера`
    - при наличии комиссий:
      - `ОплатаКомиссииБрокераПерваяЧасть`
      - `ОплатаКомиссииБиржиПерваяЧасть`
    - все ветки сходятся в `Слияние1` → `ВтораяЧастьРЕПО` → `Разделение2`:
      - `ОплатаВторойЧастиСделкиЧерезБрокера`
      - при наличии комиссий:
        - `ОплатаКомиссииБрокераВтораяЧасть`
        - `ОплатаКомиссииБиржиВтораяЧасть`
      - все ветки сходятся в `Слияние2` → `Завершение`.

- **Что выполняется сразу при старте:**
  - Для точки `УстановкаНастроекБП` обработчик `УстановкаНастроекБизнесПроцессаПриСозданииЗадач`:
    - создает задачу `Задачи.ВнебиржеваяСделка.СоздатьЗадачу()`;
    - сразу выполняет ее `Задача.ВыполнитьЗадачу()`;
    - вызывает `БизнесПроцессы.СделкиРЕПО.ПриСозданииЗадач(...)`.
  - В результате **задача по установке настроек не остается открытой**, она закрывается автоматически.

- **Какие задачи создаются и остаются открытыми:**
  - `ПерваяЧастьРЕПО` — создание 1-й части РЕПО, срок = `ДатаПеререгистрацииПервойЧастиСделкиРЕПО`.
  - `ОплатаПервойЧастиСделкиЧерезБрокера` — оплата 1-й части, срок = `ДатаОплатыПервойЧастиСделкиРЕПО`.
  - `ОплатаКомиссииБрокераПерваяЧасть` — если `КомиссияБрокераПервойЧастиРЕПО > 0`, срок = `ДатаОплатыКомиссииБрокераПервойЧастиРЕПО`.
  - `ОплатаКомиссииБиржиПерваяЧасть` — если `КомиссияБиржиПервойЧастиРЕПО > 0`, срок = `ДатаОплатыКомиссииБиржиПервойЧастиРЕПО`.
  - `ВтораяЧастьРЕПО` — создание 2-й части РЕПО, срок = `ДатаПеререгистрацииВторойЧастиСделкиРЕПО`.
  - `ОплатаВторойЧастиСделкиЧерезБрокера` — оплата 2-й части, срок = `ДатаОплатыВторойЧастиСделкиРЕПО`.
  - `ОплатаКомиссииБрокераВтораяЧасть` — если `КомиссияБрокераВторойЧастиРЕПО > 0`, срок = `ДатаОплатыКомиссииБрокераВторойЧастиРЕПО`.
  - `ОплатаКомиссииБиржиВтораяЧасть` — если `КомиссияБиржиВторойЧастиРЕПО > 0`, срок = `ДатаОплатыКомиссииБиржиВторойЧастиРЕПО`.

- **Когда и как эти задачи выполняются:**
  - При установленном флаге `АвтоматическоеВыполнениеЗадач`:
    - задачи по СделкиРЕПО подбираются регламентной операцией **«Исполнение плановой позиции»** при закрытии периода (аналогично СделкиTn);
    - для каждой открытой задачи создается объект задачи и вызывается `ВыполнитьЗадачу()`, что запускает обработчики `...ПриВыполнении` (оформление частей РЕПО и оплат комиссий).
  - Дополнительно задачи могут выполняться вручную пользователем из списка задач.

#### 4.1.2. СделкиTn

**Условие создания (после отбора НЕ РЕПО, НЕ срочного рынка и НЕ валютных сделок):**

- Режим торгов содержит `SPB` (кроме `SPBPUT`)  
  **ИЛИ**
- `Лев(РежимТоргов, 2) = "TQ"` (классические T+ режимы, например `TQBR`, `TQTF` и т.п.)  
  **ИЛИ**
- `РежимТоргов = "OCBR"`  
  **ИЛИ**
- `НачалоДня(ДатаСделки) <> НачалоДня(ДатаРасчетов)` (любая T+n-сделка, где дата сделки и дата расчётов разные).

Если ни одно из перечисленных условий не выполняется (и сделка не попала в РЕПО, срочный или валютный рынок), то создаётся **Документ.Сделка**, а не БП `СделкиTn` (см. раздел 4.2.1).

**Характеристики:**

- Создается через `БизнесПроцессы.СделкиTn.СоздатьБизнесПроцесс()`
- Проводится сразу: `ТекСделка.Записать(РежимЗаписиДокумента.Проведение)`
- Автоматическое выполнение задач: `АвтоматическоеВыполнениеЗадач = Истина`

**Ключевые реквизиты:**

- НомерСделки, Дата, ВидОперации (Поступление/Продажа)
- ДоговорДУ, Актив, Количество, Цена
- НКД, ДатаОплатыСделки, ДатаПоставки
- КомиссияБиржи, КомиссияБрокера
- ДатаОплатыКомиссииБиржи, ДатаОплатыКомиссииБрокера

### 4.2. Документы

#### 4.2.1. Сделка

**Условие создания:**

- НЕ выполняется условие для создания БП СделкиTn (т.е. НЕ `Лев(РежимТоргов,2) = "TQ"` И НЕ `РежимТоргов = "OCBR"` И НЕ `НачалоДня(ДатаСделки) <> НачалоДня(ДатаРасчетов)`)
- И `ТекСтрока.Сделка.Пустая()` (т.е. не найдена существующая сделка для обновления)

**Характеристики:**

- Создается через `Документы.Сделка.СоздатьДокумент()`
- Или получается существующий объект через `ТекСтрока.Сделка.ПолучитьОбъект()` (если сделка уже существует)
- Проводится сразу: `ТекСделка.Записать(РежимЗаписиДокумента.Проведение)`

**Ключевые реквизиты:**

- НомерВходящегоДокумента (соответствует НомерСделки из внешней системы)
- Дата, ВидОперации (Поступление/Продажа)
- ДоговорДУ, Актив, Количество, Цена
- НКД, ДатаОплатыСделки, ДатаПоставки
- КомиссияБиржи, КомиссияБрокера
- ВнебиржеваяСделка (устанавливается в Ложь для обычных сделок)

**Особенности:**

- Используется для обычных биржевых сделок (не T+0, не РЕПО, не срочный рынок)
- Может быть обновлен, если уже существует в базе

#### 4.2.2. СделкаНаСрочномРынке

**Условие создания:** `ЭтоСделкаСрочногоРынка = Истина`

**Характеристики:**

**Ключевые реквизиты:**

- НомерСделки, Дата, ВидОперации
- Контракт (Актив), Количество
- ОпционнаяПремия (для опционов)
- КомиссияБиржи, КомиссияТС, КомиссияБрокера (в ДопРасходы)

#### 4.2.3. СделкаНаВалютномРынке

**Условие создания:** `ЭтоВалютнаяСделка = Истина`

**Характеристики:**

- Создается через `Документы.СделкаНаВалютномРынке.СоздатьДокумент()`
- Проводится сразу: `ТекСделка.Записать(РежимЗаписиДокумента.Проведение)`

**Ключевые реквизиты:**

- НомерСделки, Дата, ВидОперации

## 5. Определение существования объектов в базе

### 5.1. Массовая проверка существования

**Метод:** `ОтобратьСделкиПоНомеру(ИсходныеСделки)`

**Назначение:**
Массовая проверка существования сделок по номеру для всех входящих сделок из внешней системы. Это позволяет избежать множественных запросов к базе данных и значительно ускоряет процесс проверки.

**Принцип работы:**

1. **Создание временной таблицы:**
   - Создается временная таблица `втИсходныеСделки` с уникальными комбинациями:
     - `НомерСделки`
     - `ЭтоПродажа` (признак продажи)
     - `ЭтоВалютнаяСделка`
     - `ЭтоСделкаСрочногоРынка`
   - Индексируется по `НомерСделки, ЭтоПродажа` для быстрого поиска

2. **Выполнение сложного запроса с LEFT JOIN:**
   Запрос проверяет существование сделок во всех возможных типах объектов:

   - **Документ.Сделка:**
     - Поиск по `НомерВходящегоДокумента = НомерСделки`
     - Учитывается `ВидОперации` (Поступление для покупки, Продажа для продажи)
     - Исключаются удаленные: `ПометкаУдаления = ЛОЖЬ`
     - Применяется только для НЕ валютных и НЕ срочных сделок

   - **БизнесПроцесс.СделкиTn:**
     - Поиск по `НомерСделки = НомерСделки`
     - Учитывается `ВидОперации` (Поступление/Продажа)
     - Исключаются удаленные
     - Применяется только для НЕ валютных и НЕ срочных сделок

   - **БизнесПроцесс.ВнебиржеваяСделка:**
     - Поиск по `НомерСделки = НомерСделки` (или `Номер = НомерСделки`)
     - Учитывается `ВидОперации` (Покупка/Продажа)
     - Исключаются удаленные
     - Применяется только для НЕ валютных и НЕ срочных сделок

   - **Документ.СделкаНаСрочномРынке:**
     - Поиск по `НомерСделки = НомерСделки`
     - Учитывается `ВидОперации` (Покупка/Продажа)
     - Исключаются удаленные
     - Применяется только для сделок срочного рынка

   - **БизнесПроцесс.СделкиРЕПО:**
     - Поиск по `НомерСделки = НомерСделки`
     - НЕ учитывается ВидОперации (для РЕПО достаточно номера)
     - Исключаются удаленные
     - Применяется только для НЕ валютных сделок

   - **Документ.СделкаНаВалютномРынке:**
     - Поиск по `НомерСделки = НомерСделки`
     - Учитывается `ВидОперации` (Покупка/Продажа)
     - Исключаются удаленные
     - Применяется только для валютных сделок

3. **Группировка результатов:**
   - Результаты группируются по `НомерСделки, ЭтоПродажа, ЭтоВалютнаяСделка`
   - Используется функция `МАКСИМУМ()` для выбора найденной ссылки из всех типов
   - Формируется флаг `ЕстьСделка` (ИСТИНА, если найдена хотя бы одна сделка)

4. **Возврат результата:**
   - Возвращается таблица значений с колонками:
     - `НомерСделки`
     - `ЭтоПродажа`
     - `ЭтоВалютнаяСделка`
     - `Сделка` (ссылка на найденную сделку или NULL)
     - `ЕстьСделка` (флаг существования)
   - Добавляется индекс по `НомерСделки, ЭтоПродажа` для быстрого поиска

**Преимущества подхода:**

- ✅ Один запрос вместо множественных проверок
- ✅ Проверка всех типов сделок одновременно
- ✅ Учет всех критериев (номер, вид операции, тип сделки)
- ✅ Исключение удаленных сделок
- ✅ Индексированный результат для быстрого поиска

**Критерии поиска:**

- `НомерСделки` (или `НомерВходящегоДокумента` для Документ.Сделка)
- `ВидОперации` (соответствует типу операции: Покупка/Продажа/Поступление)
- `ПометкаУдаления = ЛОЖЬ`
- Тип сделки (валютная, срочный рынок, обычная)

### 5.2. Проверка конкретной сделки

**Метод:** `УжеЕстьСделкаПоНомеру(ТаблицаНайденныхСделок, НомерСделки, ЭтоПродажа, ЭтоВалютнаяСделка)`

**Принцип работы:**

1. Поиск в таблице результатов массовой проверки
2. Использование индекса по `НомерСделки, ЭтоПродажа`
3. Возврат значения флага `ЕстьСделка`

### 5.3. Старая проверка (не используется)

**Метод:** `СделкаПоНомеру(Номер, Продажа)` - закомментирован, заменен на массовую проверку

## 6. Проведение документов и запуск бизнес-процессов

### 6.1. Документы

**Режим проведения:**

- **Сделка:** Проводятся сразу при записи

  ```bsl
  ТекСделка.Записать(РежимЗаписиДокумента.Проведение);
  ```

- **СделкиTn:** Проводятся сразу при записи

  ```bsl
  ТекСделка.Записать(РежимЗаписиДокумента.Проведение);
  ```

- **СделкаНаСрочномРынке:** Проводятся сразу при записи

  ```bsl
  ТекСделка.Записать(РежимЗаписиДокумента.Проведение);
  ```

- **СделкаНаВалютномРынке:** Проводятся сразу при записи

  ```bsl
  ТекСделка.Записать(РежимЗаписиДокумента.Проведение);
  ```

### 6.2. Бизнес-процессы

**Режим запуска:**

- **СделкиРЕПО:**
  - Записывается без проведения: `ТекСделка.Записать()`
  - Запускается: `ТекСделка.Старт()`
  - Автоматическое выполнение задач: `АвтоматическоеВыполнениеЗадач = Истина`

- **СделкиTn:**
  - Проводится сразу при записи (как документ)
  - Автоматическое выполнение задач: `АвтоматическоеВыполнениеЗадач = Истина`

#### 6.2.1. Маршрут и задачи БП СделкиTn

**Маршрут по карте БП (упрощенно):**

- `Старт` → `УстановкаНастроекБП` → `ОткрытиеПлановойПозиции` → `Разделение1` →
  - `ОплатаСделки`
  - `ЗакрытиеПлановойПозиции`
  - `ЕстьКомиссияБрокера` → `ОплатаКомиссииБрокера`
  - `ЕстьКомиссияБиржи` → `ОплатаКомиссииБиржи`
  - Все ветки сходятся в `Слияние1` → `Завершение`.

**Что выполняется автоматически при старте:**

- При создании БП и включенном флаге `АвтоматическоеВыполнениеЗадач` движок задач вызывает обработчики модуля объекта БП:
  - Для точки `УстановкаНастроекБП` процедура `УстановкаНастроекБизнесПроцессаПриСозданииЗадач`:
    - Создает задачу `Задачи.ВнебиржеваяСделка.СоздатьЗадачу()`
    - Сразу же выполняет ее вызовом `Задача.ВыполнитьЗадачу()`
    - Вызывает `БизнесПроцессы.СделкиTn.ПриСозданииЗадач(ЭтотОбъект, ФормируемыеЗадачи, ТочкаМаршрутаБизнесПроцесса)` для дополнительной настройки
- В результате **задача по точке УстановкаНастроекБП не остается открытой**, она закрывается автоматически.

**Какие задачи остаются открытыми после старта:**

- После прохождения `УстановкаНастроекБП` создаются, но не выполняются автоматически следующие задачи:
  - `ОткрытиеПлановойПозиции`
  - `ОплатаСделки`
  - `ОплатаКомиссииБрокера` (если `КомиссияБрокера > 0`)
  - `ОплатаКомиссииБиржи` (если `КомиссияБиржи > 0`)
  - `ЗакрытиеПлановойПозиции`

**Как задачи добиваются:**

- Регламентная процедура `БизнесПроцессы.СделкиTn.ИсполнениеПлановойПозиции(Дата, Отказ, ТекстОтказа, ...)`:
  - Выбирает открытые задачи по БП СделкиTn через `ПолучитьОткрытыеЗадачиПоСделкеTn()`
  - Для каждой задачи:
    - Получает объект задачи `ТекЗадача.Ссылка.ПолучитьОбъект()`
    - Устанавливает `СинхронизоватьПредметПоЗадаче = Истина`
    - Вызывает `ТекОбъект.ВыполнитьЗадачу()`
- Конкретные действия при выполнении каждой задачи инкапсулированы в обработчиках `...ПриСозданииЗадач` и `...ПриВыполнении` модуля объекта БП (оформление открытия/закрытия позиции, оплаты сделки, оплаты комиссий).

**Этапы и их вход/выход (укрупнённо):**

- **УстановкаНастроекБП**
  - **Вход:** новый БП `СделкиTn` с заполненными реквизитами (ДоговорДУ, Актив, ВидОперации, суммы, комиссии, аналитика).  
  - **Выход:** созданы и сразу выполнены задачи по установке настроек (через `УстановкаНастроекБизнесПроцессаПриСозданииЗадач` и `ВыполнитьЗадачу()`), БП приведён в консистентное состояние, открытых задач по этой точке нет.

- **ОткрытиеПлановойПозиции**
  - **Вход:** БП с настроенными параметрами, открытая «плановая» сделка (кол-во, цена, НКД, аналитика).  
  - **Выход:** оформлено открытие плановой позиции по активу в портфеле ДУ (`ОформитьОткрытиеПлановойПозиции`), в регистрах позиций появляется плановая позиция, задача закрыта.

- **ОплатаСделки**
  - **Вход:** данные о сумме сделки, валюте, курсе, `ДатаОплатыСделки`, аналитический счёт ДС.  
  - **Выход:** оформлен платёж по сделке (`ОплатаСделки`/`ОплатаСделкиПриВыполнении`), движения по денежным средствам и расчётам с брокером/биржей, задача закрыта.

- **ОплатаКомиссииБрокера / ОплатаКомиссииБиржи**
  - **Вход:** рассчитанные комиссии (суммы, валюты, счета учёта), даты оплаты комиссий.  
  - **Выход:** оформлены документы оплаты комиссий и движения по счетам комиссий/ДС, комиссии отражены в расходах или кредиторской задолженности согласно учётной политике, задачи закрыты.

- **ЗакрытиеПлановойПозиции**
  - **Вход:** открытая плановая позиция по активу, данные о фактическом исполнении (кол-во, курс, НКД, уже выполненные оплаты).  
  - **Выход:** закрыта плановая позиция (`ОформитьЗакрытиеПлановойПозиции`), сформированы движения по активу и результат по сделке (доход/убыток), задача закрыта; после выполнения всех задач БП может перейти в `Завершение`.

## 8. Логика определения типа сделки

### 8.1. Алгоритм определения

1. **СделкиРЕПО:**
   - Режим торгов содержит: `RP`, `RD`, `RE`, `WP`, `WD`, `WE`, `PSRY`
   - Или `EQ` + `BND`
   - Или `ЭтоРЕПО_КСУ(РежимТоргов) = Истина`

2. **СделкаНаСрочномРынке:**
   - `ЭтоСделкаСрочногоРынка(Актив) = Истина`
   - Проверяется через запрос: `Актив.ВидАктива В ИЕРАРХИИ(СрочныеКонтракты)`

3. **СделкиTn:**
   - Режим торгов содержит `SPB` (кроме `SPBPUT`)
   - Или `Лев(РежимТоргов,2) = "TQ"` ИЛИ `РежимТоргов = "OCBR"` ИЛИ `НачалоДня(ДатаСделки) <> НачалоДня(ДатаРасчетов)`
   - Создается как бизнес-процесс

4. **Сделка (документ):**
   - НЕ выполняется условие для СделкиTn
   - НЕ соответствует другим типам сделок
   - Создается как документ (не бизнес-процесс)

5. **СделкаНаВалютномРынке:**
   - `ЭтоВалютнаяСделка = Истина`
   - Определяется при парсинге данных из веб-сервиса
