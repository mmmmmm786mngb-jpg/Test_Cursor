## 2. Кэширование справочников

### 2.1. Проблема

В процедуре `ПрочитатьНаСервере()` (строки 2543-2877) выполняется множество обращений к справочникам внутри цикла обработки сделок. Каждый вызов `НайтиПоНаименованию()` или `НайтиПоКоду()` выполняет запрос к базе данных, что критически замедляет обработку при большом количестве сделок.

**Места в коде:**

- **Строка 2588:** `Биржа = Справочники.Биржи.НайтиПоНаименованию(НаименованиеБиржи);`
- **Строка 2593:** `НоваяСделка.Биржа = Справочники.Биржи.НайтиПоКоду("СПБФБ");`
- **Строка 2752:** `Валюта = Справочники.Валюты.НайтиПоНаименованию(ТекСделка.ВалютаСделки);`
- **Строка 1066:** `РежимыТоргов.Добавить(Справочники.РежимыТоргов.НайтиПоНаименованию("OPTSPOT"));`
- **Строка 1067:** `РежимыТоргов.Добавить(Справочники.РежимыТоргов.НайтиПоНаименованию("PSOPTSPOT"));`
- **Строка 1170:** `ТекСделка.СчетУчетаВзаиморасчетов = ?(ТекСтрока.Продажа,ПланыСчетов.Хозрасчетный.НайтиПоКоду("76.03"),ПланыСчетов.Хозрасчетный.НайтиПоКоду("76.02"));`
- **Строка 1206:** `ТекСделка.СчетУчетаДопРасходов = ПланыСчетов.Хозрасчетный.НайтиПоКоду("97");`
- **Строка 1219:** `ТекСделка.СчетДЕПОКонтрагента = Справочники.СчетаДепо.НайтиПоНаименованию(...);`
- **Строка 1348:** `ТекСделка.СтатьяРасходовКомиссииБрокера = Справочники.СтатьиДоходовИРасходов.НайтиПоНаименованию("Комиссия брокера");`
- **Строка 1349:** `ТекСделка.СтатьяРасходовКомиссииБиржи = Справочники.СтатьиДоходовИРасходов.НайтиПоНаименованию("Комиссия биржи");`

**Оценка влияния:** При обработке 1000 сделок выполняется ~3000-5000 запросов к справочникам. Это критическое узкое место.

### 2.2. Решение

Создать кэш справочников перед циклом обработки и использовать его внутри цикла.

**Было:**

```bsl
// В цикле ПрочитатьНаСервере(), строка 2588
Для Каждого ТекСделка из Сделки Цикл
    // ...
    НаименованиеБиржи = ТекСделка.Биржа.Наименование;
    Биржа = Справочники.Биржи.НайтиПоНаименованию(НаименованиеБиржи); // Запрос к БД
    // ...
    Валюта = Справочники.Валюты.НайтиПоНаименованию(ТекСделка.ВалютаСделки); // Запрос к БД
    // ...
КонецЦикла;
```

**Стало:**

```bsl
// Перед циклом ПрочитатьНаСервере(), после строки 2534
// Создание кэшей справочников
КэшБирж = Новый Соответствие;
КэшВалют = Новый Соответствие;
КэшРежимовТоргов = Новый Соответствие;
КэшСчетов = Новый Соответствие;
КэшСтатейРасходов = Новый Соответствие;
КэшСчетовДепо = Новый Соответствие;

// Предзагрузка только тех элементов, которые сразу известны (константы, часто используемые)
КэшСчетов.Вставить("76.02", ПланыСчетов.Хозрасчетный.НайтиПоКоду("76.02"));
КэшСчетов.Вставить("76.03", ПланыСчетов.Хозрасчетный.НайтиПоКоду("76.03"));
КэшСчетов.Вставить("97", ПланыСчетов.Хозрасчетный.НайтиПоКоду("97"));
КэшСчетов.Вставить("91.02.04", ПланыСчетов.Хозрасчетный.НайтиПоКоду("91.02.04"));

КэшСтатейРасходов.Вставить("Комиссия брокера", Справочники.СтатьиДоходовИРасходов.НайтиПоНаименованию("Комиссия брокера"));
КэшСтатейРасходов.Вставить("Комиссия биржи", Справочники.СтатьиДоходовИРасходов.НайтиПоНаименованию("Комиссия биржи"));

КэшБирж.Вставить("СПБФБ", Справочники.Биржи.НайтиПоКоду("СПБФБ"));
КэшБирж.Вставить("ММВБ", Справочники.Биржи.НайтиПоНаименованию("ММВБ"));

// В основном цикле обработки сделок (строка 2543) - дозаполнение кэша по мере необходимости
Для Каждого ТекСделка из Сделки Цикл
    // ...
    НаименованиеБиржи = ТекСделка.Биржа.Наименование;
    Биржа = КэшБирж.Получить(НаименованиеБиржи);
    Если Биржа = Неопределено Тогда
        // Дозаполнение кэша при первом обращении
        Биржа = Справочники.Биржи.НайтиПоНаименованию(НаименованиеБиржи);
        КэшБирж.Вставить(НаименованиеБиржи, Биржа);
    КонецЕсли;
    
    // ...
    Валюта = КэшВалют.Получить(ТекСделка.ВалютаСделки);
    Если Валюта = Неопределено Тогда
        // Дозаполнение кэша при первом обращении
        Валюта = Справочники.Валюты.НайтиПоНаименованию(ТекСделка.ВалютаСделки);
        Если НЕ Валюта.Пустая() Тогда
            КэшВалют.Вставить(ТекСделка.ВалютаСделки, Валюта);
        КонецЕсли;
    КонецЕсли;
    
    // Аналогично для других справочников
    // ...
КонецЦикла;
```

**Ожидаемый эффект:** Сокращение количества запросов к БД с ~3000-5000 до ~50-100 (только уникальные значения). Ускорение на **30-50%**.

## 3. Оптимизация запроса проверки существования

### 3.1. Проблема

Функция `ОтобратьСделкиПоНомеру()` (строки 2139-2383) выполняет сложный запрос с множественными LEFT JOIN и UNION. Запрос проверяет существование сделок во всех типах объектов одновременно, что хорошо, но можно оптимизировать через индексы и фильтры по дате.

**Текущий запрос:** Строки 2144-2377 содержат запрос с:

- UNION блоки для проверки в трех типах объектов: `Документ.Сделка`, `БизнесПроцесс.СделкиTn`, `БизнесПроцесс.СделкиРЕПО`
- Множественные LEFT JOIN
- Группировка результатов
- Поиск по указанным типам объектов без фильтрации по дате

**Оценка влияния:** При большом объеме данных в базе запрос может выполняться 5-30 секунд.

### 3.2. Решение

1. **Добавить индексы** на поля, используемые в запросе
2. **Добавить фильтр по дате** для ограничения выборки
3. **Оптимизировать структуру запроса**

#### 3.2.2. Рекомендации по индексам

**✅ НУЖНО создать индексы на:**

     - `БизнесПроцесс.СделкиРЕПО`: `(НомерСделки, ПометкаУдаления, Дата)` - без ВидОперации, т.к. не используется в запросе

**❌ НЕ НУЖНО создавать индексы на:**

1. **Поля с низкой селективностью:**
   - `ПометкаУдаления` - булево поле (только 2 значения), неэффективно как отдельный индекс
   - Используется только в составе составных индексов

2. **Поля, не участвующие в условиях поиска:**
   - Поля, которые не используются в `WHERE`, `JOIN`, `ORDER BY` запроса
   - Например: `Сумма`, `Количество`, `Цена` - не используются в запросе `ОтобратьСделкиПоНомеру()`

3. **Поля с частыми обновлениями без использования в поиске:**
   - Поля, которые часто изменяются, но не используются в условиях запросов

#### 3.2.3. Приоритет внедрения индексов

**Высокий приоритет (критично для производительности):**

1. `БизнесПроцесс.СделкиTn.НомерСделки` - Index
2. `БизнесПроцесс.СделкиРЕПО.НомерСделки` - Index

**Низкий приоритет (опционально, для дальнейшей оптимизации):**
3. Составные индексы для всех объектов (если после добавления простых индексов производительность все еще недостаточна):

- `Документ.Сделка`: `(НомерВходящегоДокумента, ВидОперации, ПометкаУдаления, Дата)`
- `БизнесПроцесс.СделкиTn`: `(НомерСделки, ВидОперации, ПометкаУдаления, Дата)`
- `БизнесПроцесс.СделкиРЕПО`: `(НомерСделки, ПометкаУдаления, Дата)`

**Ожидаемый эффект:**

- После добавления индексов на `НомерСделки`: ускорение запроса в **3-5 раз**
- После добавления фильтрации по дате: дополнительное ускорение в **1.5-2 раза**
- Общее ускорение: **4-10 раз** в зависимости от объема данных

## 5. Оптимизация логирования

### 5.1. Проблема

В процедурах `ЗагрузитьОбъекты()` и `СоздатьОбъекты()` создается объект `ТабличныйДокумент` и выполняется множество вызовов `Лог.Вывести()` для каждой обрабатываемой сделки. Это замедляет выполнение, особенно при большом количестве сделок.

**Места в коде:**

- **Строка 893:** `Лог = Новый ТабличныйДокумент;`
- **Строка 1077:** `Лог.Вывести(ЗаголовокТаблицы);`
- **Строки 1111, 1121, 1131, 1141:** `Лог.Вывести(СтрокаДокументов);` - в цикле для каждой сделки
- **Строка 156:** `Задача.ХранилищеЛога = Новый ХранилищеЗначения(Лог, Новый СжатиеДанных(9));`

**Оценка влияния:** При обработке 1000 сделок выполняется ~1000 вызовов `Лог.Вывести()`, что может занимать 5-15% времени выполнения.

### 5.2. Решение

1. **Собирать данные лога в таблицу значений**, а не сразу выводить в ТабличныйДокумент
2. **Выводить лог только при ошибках** в продакшене
3. **Формировать ТабличныйДокумент один раз** в конце обработки

**Было:**

```bsl

Лог.ОтображатьЗаголовки  = Ложь;

Заголовок = Макет.ПолучитьОбласть("Заголовок");
Лог.Вывести(Заголовок);

// В цикле СоздатьОбъекты(), строка 1111
Для Каждого ТекСтрока из СписокЗагрузки Цикл
    // ...
    СтрокаДокументов.Параметры.Заполнить(ТекСтрока);
    СтрокаДокументов.Параметры.ОшибкаСделки = ТекстОшибки;
    СтрокаДокументов.Параметры.ЕстьОшибки = "ДА";
    Лог.Вывести(СтрокаДокументов); // Вывод в каждой итерации
    // ...

```

**Стало:**


## 6. Параллельная обработка через фоновые задания

### 6.1. Проблема

Процедура `СоздатьОбъекты()` (строки 1073-2155) последовательно обрабатывает все сделки из `СписокЗагрузки`. При большом объеме данных (тысячи сделок) это занимает много времени. Сделки могут относиться к разным `ДоговорДУ`, которые являются основным разделителем учета в конфигурации.

**Текущая реализация:**

- Строка 1103: `Для Каждого ТекСтрока из СписокЗагрузки Цикл`
- Внутри цикла: создание объекта, заполнение, запись, проведение
- Все выполняется последовательно в одном потоке, независимо от `ДоговорДУ`

**Оценка влияния:** При обработке 5000 сделок последовательная обработка может занимать 30-60 минут. При этом сделки разных договоров могут обрабатываться параллельно, так как они не зависят друг от друга.

### 6.2. Решение

Разделить список загрузки на группы по `ДоговорДУ` (основной разделитель учета в конфигурации) и обрабатывать каждую группу параллельно через фоновые задания.

**Было:**

```bsl
// Строка 1103: Последовательная обработка
Для Каждого ТекСтрока из СписокЗагрузки Цикл
    // Определение типа сделки
    Если ТекСтрока.РежимТоргов.Наименование = "OTC" Тогда
        // Создание ВнебиржеваяСделка
    ИначеЕсли ... Тогда
        // Создание СделкиРЕПО
    ИначеЕсли ... Тогда
        // Создание СделкиTn
    // ...
    // Запись и проведение
    ТекСделка.Записать(РежимЗаписиДокумента.Проведение);
КонецЦикла;
```


**Ожидаемый эффект:**

- При наличии достаточных ресурсов (несколько ядер CPU) и нескольких договоров в загрузке ускорение в **2-4 раза** за счет параллельной обработки
- Каждый договор обрабатывается в отдельном фоновом задании, что обеспечивает изоляцию данных и возможность параллельного выполнения
- Максимальное количество параллельных заданий ограничено **10 потоками**, что предотвращает перегрузку системы
- При количестве договоров больше 10 организуется очередь с динамическим пополнением: как только одно задание завершается, запускается следующее
- При одном договоре эффект минимален, при 5-10 договорах - максимальный (до 4x ускорения)
- При большом количестве договоров (20-50) эффект сохраняется за счет постоянной загрузки всех 10 потоков

- `АктивПоКоду()` (строка 2698)
- `ВалютаПоКоду()` (строки 2610, 2625)
- `ТорговыйКодПоКоду()` (строки 2509, 2674, 2679, 2768)
- `ПолучитьБрокераПоКоду()` (строки 2686, 2775)
- `ПолучитьКурсВалюты()` (строка 2756)

**Решение:** Создать кэши для результатов этих функций аналогично кэшированию справочников.

**Пример:**

```bsl
// Было: в цикле для каждой строки
Для Каждого ТекСтрока Из СписокЗагрузки Цикл
    Актив = АктивПоКоду(ТекСтрока.КодАктива); // Запрос к БД каждый раз
    Валюта = ВалютаПоКоду(ТекСтрока.КодВалюты); // Запрос к БД каждый раз
    ТорговыйКод = ТорговыйКодПоКоду(ТекСтрока.КодТорговогоКода); // Запрос к БД каждый раз
КонецЦикла;

// Стало: динамическое заполнение кэша в основном цикле
КэшАктивов = Новый Соответствие;
КэшВалют = Новый Соответствие;
КэшТорговыхКодов = Новый Соответствие;
КэшБрокеров = Новый Соответствие;
КэшКурсовВалют = Новый Соответствие;

// Предзаполняем кэш только известными константами (если есть)
// Например, если есть часто используемые валюты:
КэшВалют.Вставить("RUB", Справочники.Валюты.НайтиПоКоду("RUB"));
КэшВалют.Вставить("USD", Справочники.Валюты.НайтиПоКоду("USD"));
КэшВалют.Вставить("EUR", Справочники.Валюты.НайтиПоКоду("EUR"));

// Основной цикл обработки - дозаполняем кэш по мере необходимости
Для Каждого ТекСтрока Из СписокЗагрузки Цикл
    // Получаем актив из кэша или добавляем в кэш
    Если НЕ КэшАктивов.Получить(ТекСтрока.КодАктива) Тогда
        КэшАктивов.Вставить(ТекСтрока.КодАктива, АктивПоКоду(ТекСтрока.КодАктива));
    КонецЕсли;
    Актив = КэшАктивов[ТекСтрока.КодАктива]; // Без запроса к БД при повторном использовании
    
    // Получаем валюту из кэша или добавляем в кэш
    Если НЕ КэшВалют.Получить(ТекСтрока.КодВалюты) Тогда
        КэшВалют.Вставить(ТекСтрока.КодВалюты, ВалютаПоКоду(ТекСтрока.КодВалюты));
    КонецЕсли;
    Валюта = КэшВалют[ТекСтрока.КодВалюты]; // Без запроса к БД при повторном использовании
    
    // Получаем торговый код из кэша или добавляем в кэш
    Если НЕ КэшТорговыхКодов.Получить(ТекСтрока.КодТорговогоКода) Тогда
        КэшТорговыхКодов.Вставить(ТекСтрока.КодТорговогоКода, ТорговыйКодПоКоду(ТекСтрока.КодТорговогоКода));
    КонецЕсли;
    ТорговыйКод = КэшТорговыхКодов[ТекСтрока.КодТорговогоКода]; // Без запроса к БД
    
    // Аналогично для брокеров и курсов валют
    Если НЕ КэшБрокеров.Получить(ТекСтрока.КодБрокера) Тогда
        КэшБрокеров.Вставить(ТекСтрока.КодБрокера, ПолучитьБрокераПоКоду(ТекСтрока.КодБрокера));
    КонецЕсли;
    Брокер = КэшБрокеров[ТекСтрока.КодБрокера];
    
    // Для курсов валют - ключ может быть составным (валюта + дата)
    КлючКурса = ТекСтрока.КодВалюты + "_" + Формат(ТекСтрока.Дата, "ДФ=yyyyMMdd");
    Если НЕ КэшКурсовВалют.Получить(КлючКурса) Тогда
        КэшКурсовВалют.Вставить(КлючКурса, ПолучитьКурсВалюты(Валюта, ТекСтрока.Дата));
    КонецЕсли;
    КурсВалюты = КэшКурсовВалют[КлючКурса];
    
    // ... дальнейшая обработка строки с использованием закэшированных значений
КонецЦикла;
```

**Ожидаемый эффект:** Ускорение на **10-20%**.

### 7.2. Минимизация обращений к полям через точку с помощью ЗначениеРеквизитовОбъекта

**Проблема:** В коде используются обращения к полям объектов через точку внутри циклов (например, `ТекСтрока.Актив.Объект.ВалютаНоминальнойСтоимости`, строка 1178), что приводит к множественным обращениям к БД для получения объекта. При каждом обращении через точку происходит загрузка полного объекта в память, что неэффективно, если нужны только отдельные реквизиты.

**Решение:** Использовать функции общего модуля `ОбщегоНазначения`:

- `ПолучитьЗначениеРеквизита(Ссылка, ИмяРеквизита)` - для получения одного реквизита
- `ЗначениеРеквизитаОбъекта(Ссылка, ИмяРеквизита)` - альтернатива для одного реквизита
- `ЗначенияРеквизитовОбъекта(Ссылка, Реквизиты)` - для получения нескольких реквизитов за один запрос

**Описание функций (из эталонной конфигурации):**

- **`ПолучитьЗначениеРеквизита`** - возвращает значение реквизита, прочитанного из информационной базы по ссылке на объект. Выполняет запрос к БД только для чтения нужного реквизита, без загрузки полного объекта в память.
- **`ЗначениеРеквизитаОбъекта`** - аналогична `ПолучитьЗначениеРеквизита`, но использует внутренне `ЗначенияРеквизитовОбъекта`.
- **`ЗначенияРеквизитовОбъекта`** - возвращает структуру с несколькими реквизитами, прочитанными одним запросом. Параметр `Реквизиты` может быть строкой (имена через запятую) или массивом.

**Пример:**

```bsl
// Было: прямое обращение через точку (загружает объект в память каждый раз)
Для Каждого ТекСтрока Из СписокЗагрузки Цикл
    ТекСделка.ВалютаАктива = ТекСтрока.Актив.Объект.ВалютаНоминальнойСтоимости; // Загрузка объекта
    ТекСделка.Биржа = ТекСтрока.Актив.Объект.БиржаЛистинга; // Еще одна загрузка объекта
    ТекСделка.Лот = ТекСтрока.Актив.Объект.Лот; // Еще одна загрузка объекта
КонецЦикла;

// Стало: использование ПолучитьЗначениеРеквизита для одного реквизита
Для Каждого ТекСтрока Из СписокЗагрузки Цикл
    АктивОбъект = ОбщегоНазначения.ПолучитьЗначениеРеквизита(ТекСтрока.Актив, "Объект");
    ТекСделка.ВалютаАктива = ОбщегоНазначения.ПолучитьЗначениеРеквизита(
        АктивОбъект, 
        "ВалютаНоминальнойСтоимости"
    ); // Только чтение значения, без загрузки объекта
КонецЦикла;

// Стало: использование ЗначенияРеквизитовОбъекта для множественных полей (оптимально)
Для Каждого ТекСтрока Из СписокЗагрузки Цикл
    АктивОбъект = ОбщегоНазначения.ПолучитьЗначениеРеквизита(ТекСтрока.Актив, "Объект");
    
    // Получаем несколько реквизитов одним запросом
    РеквизитыАктива = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(
        АктивОбъект, 
        "ВалютаНоминальнойСтоимости, БиржаЛистинга, Лот"
    );
    
    ТекСделка.ВалютаАктива = РеквизитыАктива.ВалютаНоминальнойСтоимости;
    ТекСделка.Биржа = РеквизитыАктива.БиржаЛистинга;
    ТекСделка.Лот = РеквизитыАктива.Лот;
    // Все значения получены одним запросом к БД
КонецЦикла;

// Пример из эталонной конфигурации (БизнесПроцесс.СделкиРЕПО):
АктивОбъект = ОбщегоНазначения.ПолучитьЗначениеРеквизита(Объект.Актив, "Объект");
Объект.ВалютаЦБ = ОбщегоНазначения.ПолучитьЗначениеРеквизита(АктивОбъект, "ВалютаНоминальнойСтоимости");

// Пример из эталонной конфигурации (БизнесПроцесс.ВнебиржеваяСделка):
Объект.ВалютаВзаиморасчетов = ОбщегоНазначения.ЗначениеРеквизитаОбъекта(Объект.ДоговорКонтрагента, "ВалютаВзаиморасчетов");

// Пример из эталонной конфигурации (Регистр.ИсторияСтавокДисконтаПоСделкамРЕПО):
РеквизитыСделкиРЕПО = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(
    Запись.СделкаРЕПО, 
    "ДоговорДУ, Дата, ДатаПрекращенияОбязательств, ВалютаДокумента, СтавкаРепо"
);
```

**Ожидаемый эффект:** Ускорение на **3-7%** за счет уменьшения количества обращений к БД и объема загружаемых данных.

### 7.3. Оптимизация работы с таблицами значений

**Проблема:** В функции `ОтобратьСделкиПоНомеру()` создается временная таблица и выполняется сложный запрос.

**Решение:** Использовать индексы на временной таблице и оптимизировать структуру запроса (убрать избыточные UNION, если возможно).

```bsl
ВТ.Колонки.Добавить("ЭтоПродажа", Новый ОписаниеТипов("Булево"));
// ... запрос с JOIN по НомерСделки, ЭтоПродажа

// Стало: явное указание индексов на временной таблице
ВТ = Запрос.ВременныеТаблицы.Добавить("втИсходныеСделки");
ВТ.Колонки.Добавить("НомерСделки", Новый ОписаниеТипов("Строка"));
ВТ.Колонки.Добавить("ЭтоПродажа", Новый ОписаниеТипов("Булево"));
ВТ.Индексы.Добавить("НомерСделки, ЭтоПродажа"); // Явный индекс для быстрого поиска
```
