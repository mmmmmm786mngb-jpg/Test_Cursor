Постановка задачи (Confluence / Jira)

Требование: В анкете выпуска ЦБ в разделе 3 оставить только поля:

  • Наименование места хранения
  • ОГРН (другой ИД) места хранения
  • № ЛС НРД
  • Тип ЛС (НД/НДЦ)

В анкету выпуска ЦБ выводить данные с закладки «Места хранения» ценной бумаги (для всех ЦБ).

Источник данных (ТЗ): строка табличной части «Места хранения» справочника «Ценная бумага», у которой реквизит «Основное место хранения» = Истина.

  • Наименование места хранения — реквизит «Наименование» ЮЛ из реквизита «Место хранения» ТЧ.
  • ОГРН (другой идентификатор) — реквизит «ОГРН» ЮЛ; если у ЮЛ страна не Россия — выводить реквизит «TIN».
  • № ЛС НРД — реквизит ТЧ «Номер лицевого счета НРД в МХ».
  • Тип ЛС (НД/НДЦД) — реквизит ТЧ «Тип лицевого счета НРД в МХ».

Сравнение постановки задачи и реализации

Критерий Постановка / ТЗ Реализация (что сделано / что не так / лишнее / не сделано)
Раздел 3: только 4 поля Оставить только: Наименование МХ, ОГРН (другой ИД), № ЛС НРД, Тип ЛС (НД/НДЦ). Сделано так Макет отчёта изменён: убраны поля реестродержателя (адреса, телефон, факс, email), оставлены заголовки и параметры РеестродержательНаименование, РеестродержательОГРН, НомерЛС_НРД, ТипЛС_НРД.
Источник данных раздела 3 Данные с закладки «Места хранения» ЦБ; строка, где ОсновноеМестоХранения = Истина. Сделано так Реализована функция ИнформацияОРеестродержателе(ЦеннаяБумага) — перебор ЦеннаяБумага.МестаХранения, возврат строки ТЧ с ОсновноеМестоХранения = Истина.
Наименование места хранения Реквизит «Наименование» ЮЛ (Место хранения ТЧ). Не так В коде: Параметры.РеестродержательНаименование = Реестродержатель.ПолноеНаименование. По ТЗ должен выводиться реквизит «Наименование» (краткое), а не ПолноеНаименование.
ОГРН / другой ИД ОГРН ЮЛ; если страна не Россия — TIN этого ЮЛ. Не так + баг (1) В коде присвоение Параметры.РеестродержательОГРН = Реестродержатель.Наименование — подставлено поле Наименование вместо ОГРН (ошибка). (2) Логика «если не Россия — выводить TIN» в процедуре ЗаполнитьПараметрыРеестродержателя не реализована.
№ ЛС НРД Реквизит ТЧ «Номер лицевого счета НРД в МХ». Сделано так Параметры.НомерЛС_НРД = ИнформацияОРеестродержателе.НомерЛицевогоСчетаНРДвМХ.
Тип ЛС (НД/НДЦД) Реквизит ТЧ «Тип лицевого счета НРД в МХ». Сделано так Параметры.ТипЛС_НРД = Строка(ИнформацияОРеестродержателе.ТипЛицевогоСчетаНРДвМХ).
Обработка отсутствия основного МХ Не описано явно. Не сделано При отсутствии строки с ОсновноеМестоХранения = Истина функция возвращает Неопределено; вызов ЗаполнитьПараметрыРеестродержателя(Параметры, Неопределено) приведёт к ошибке при обращении к ИнформацияОРеестродержателе.МестоХранения. Необходима проверка перед вызовом.
Рефакторинг модуля отчёта Не требовался. Лишнее (приемлемо) Выделены процедуры ЗаполнитьПараметрыЭмитента, ЗаполнитьПараметрыВыпускаЦБ, ЗаполнитьПараметрыРеестродержателя, ФИОСотрудника; удалены ВернутьКонтакт и ПолучитьКонтакты. Улучшает читаемость и поддержку.
Имя функции и опечатка в базе — Лишнее В базовой конфигурации в ПолучитьКонтакты использовался ключ «Юридиеский» (опечатка). В доработке эта функция удалена; в макете опечатка не исправлялась (поля убраны).

Замечания код-ревью (стандарты 1С, Sonar)

Критично: Неверное присвоение ОГРН
Отчет.АнкетаВыпускаЦБ, процедура ЗаполнитьПараметрыРеестродержателя

В параметры отчёта для «ОГРН (другой идентификатор) места хранения» записывается значение поля Наименование ЮЛ вместо ОГРН/TIN.

// ОШИБКА: в ОГРН подставляется Наименование
Параметры.РеестродержательОГРН = Реестродержатель.Наименование;

Исправление: Реализовать по ТЗ: для ЮЛ с Россией — Реестродержатель.ОГРН, для нерезидента — Реестродержатель.TIN (при наличии), и присваивать в Параметры.РеестродержательОГРН.

Критично: Возможный вызов с Неопределено
Отчет.АнкетаВыпускаЦБ, СформироватьОтчет(), вызов ЗаполнитьПараметрыРеестродержателя

ИнформацияОРеестродержателе(ЦеннаяБумага) возвращает Неопределено, если в ТЧ «Места хранения» нет строки с ОсновноеМестоХранения = Истина. Вызов ЗаполнитьПараметрыРеестродержателя(Параметры, ИнформацияОРеестродержателе) без проверки приведёт к ошибке при обращении к полям (МестоХранения, НомерЛицевогоСчетаНРДвМХ и т.д.).

ИнформацияОРеестродержателе = ИнформацияОРеестродержателе(ЦеннаяБумага);
ЗаполнитьПараметрыРеестродержателя(Параметры, ИнформацияОРеестродержателе);  // падение при Неопределено

Исправление: Перед вызовом проверять ЗначениеЗаполнено(ИнформацияОРеестродержателе) или ТипЗнч(ИнформацияОРеестродержателе) <> Тип("Неопределено"); при пустом значении заполнять параметры раздела 3 пустыми строками или не вызывать процедуру, предварительно установив пустые значения в Параметры.

Наименование МХ: ПолноеНаименование вместо Наименование
Процедура ЗаполнитьПараметрыРеестродержателя

По ТЗ в раздел 3 выводится реквизит «Наименование» ЮЛ. В коде используется ПолноеНаименование. Привести в соответствие с ТЗ: использовать Наименование (или уточнить у заказчика).

Отсутствие документирующих комментариев
Отчет.АнкетаВыпускаЦБ, новые процедуры и функция

По стандартам 1С экспортные и ключевые процедуры/функции должны иметь документирующий комментарий (Описание, Параметры, Возвращаемое значение). Добавить комментарии к: ИнформацияОРеестродержателе, ЗаполнитьПараметрыРеестродержателя, ЗаполнитьПараметрыЭмитента, ЗаполнитьПараметрыВыпускаЦБ, ФИОСотрудника.

Регистр ключевых слов: ИЗ / Или / Неопределено
Модуль объекта отчёта (сравнение с базой)

В доработке приведён регистр к стандарту 1С: Для Каждого Элемент Из ЦенныеБумаги, Или ... = Неопределено — это корректно. Убедиться, что во всём модуле используется единый стиль (Из, Или, Не, Тогда, КонецЕсли и т.д.).

Комментарий BSLLS:Typo-off для Мнемокод
Строка с Параметры.МнемокодВыпускаЦБ

Добавлен комментарий // BSLLS:Typo-off для подавления предупреждения линтера по слову «Мнемокод». Допустимо; при желании можно рассмотреть переименование параметра макета на более нейтральное (например, КодВыпускаЦБ) в перспективе.

Использование Попытка в ЗаполнитьПараметрыВыпускаЦБ

Попытка/Исключение для получения номинала ЦБ из регистра сведений — уместна, так как срез может быть пустым. Рекомендация: в Исключении при необходимости логировать причину (пустой срез и т.п.) для отладки.

Плюсы реализации
  • Логика раздела 3 переведена на данные ТЧ «Места хранения» ЦБ, как в ТЗ.
  • Рефакторинг (выделение процедур заполнения параметров) улучшает структуру модуля.
  • Макет отчёта приведён в соответствие с перечнем полей ТЗ (заголовки и параметры раздела 3).

Итоги код-ревью

Соответствие постановке

Общая идея ТЗ выполнена: раздел 3 сокращён до четырёх полей, данные берутся из ТЧ «Места хранения» ЦБ (строка с основным МХ). Критично: неверное присвоение ОГРН (подставлено Наименование) и отсутствие логики ОГРН/TIN по стране; не обработан случай отсутствия основного МХ (риск падения).

Что исправить в первую очередь

  • В ЗаполнитьПараметрыРеестродержателя: присваивать в РеестродержательОГРН значение ОГРН или TIN по правилу ТЗ (Россия — ОГРН, не Россия — TIN).
  • Устранить присвоение ОГРН из поля Наименование.
  • Перед вызовом ЗаполнитьПараметрыРеестродержателя проверять, что ИнформацияОРеестродержателе заполнена; иначе заполнять параметры раздела 3 пустыми значениями.
  • По ТЗ уточнить: Наименование МХ — краткое (Наименование) или полное (ПолноеНаименование) и привести код в соответствие.

Рекомендации

  • Добавить документирующие комментарии к новым процедурам и функции.
  • Сохранять единый стиль ключевых слов 1С по всему модулю.
