Отчет: Рефакторинг дублирующего кода в обработке загрузки сделок

Краткая сводка

Объект: внЗагрузкаСделокDU-NEW

Проблема: Обнаружено дублирование кода - 2 пары процедур с практически идентичной логикой

Решение: Параметризация оригинальных процедур для устранения дублирования

Статус: План рефакторинга разработан, готов к реализации

1. Проблема

Обнаруженное дублирование кода

Оригинальная процедура Дублирующая процедура Процент совпадения Статус
ЗагрузитьОбъекты
891 строка		 ПрочитатьСделкиРЕПО

ПрочитатьНаСервере

СоздатьОбъекты

Почему это проблема?

  • Усложнение поддержки: Изменения нужно вносить в двух местах
  • Риск рассинхронизации: При изменении одной процедуры можно забыть обновить дубль
  • Увеличение объема кода: Дублирование ~530 строк кода
  • Нарушение принципа DRY: Don't Repeat Yourself (Не повторяйся). В программировании также используется метафора "сухого кода" (dry code) - чистого, без дублирования, в противовес "мокрому коду" (wet code) с избыточными повторениями

2. Решение

Стратегия рефакторинга

Вместо удаления дублей и создания новых процедур, мы параметризуем оригинальные процедуры, добавив параметр режима работы.

Что будет сделано:

  1. Параметризация ЗагрузитьОбъекты
    • Добавление параметра РежимЗагрузки
    • При значении "РЕПО" - работа в режиме РЕПО
    • При Неопределено - обычная работа (обратная совместимость)
  2. Параметризация ПрочитатьНаСервере
    • Добавление параметра РежимЗагрузки
    • В режиме РЕПО: фильтр по РЕПО режимам торгов
    • В режиме РЕПО: инверсия логики проверки существующих сделок
  3. Удаление дублирующих процедур
    • ПрочитатьСделкиРЕПО - будет удалена
    • ПрочитатьЗагруженныеСделкиРЕПО - будет удалена

4. Ожидаемый результат

Структура вызовов до рефакторинга:

Кнопка "ПрочитатьСделкиРЕПО"
  └─> ПрочитатьСделкиРЕПО()          // Дублирующая процедура
       └─> ПрочитатьЗагруженныеСделкиРЕПО()  // Дублирующая процедура

Кнопка "Прочитать сделки"
  └─> ЗагрузитьОбъекты()
       └─> ПрочитатьНаСервере()

Структура вызовов после рефакторинга:

Кнопка "ПрочитатьСделкиРЕПО"
  └─> ЗагрузитьОбъекты(Отказ, "", "РЕПО")    // Оригинальная процедура с параметром
       └─> ПрочитатьНаСервере(..., "РЕПО")   // Оригинальная процедура с параметром

Кнопка "Прочитать сделки"
  └─> ЗагрузитьОбъекты(Отказ)                // Оригинальная процедура (без изменений)
       └─> ПрочитатьНаСервере(...)            // Оригинальная процедура (без изменений)

Удаление дублирующих процедур:

После успешного тестирования будут удалены две дублирующие процедуры:

  • ПрочитатьСделкиРЕПО - 87 строк кода (строки 3524-3611)
  • ПрочитатьЗагруженныеСделкиРЕПО - 263 строки кода (строки 3684-3947)

Итого будет удалено: ~350 строк дублирующего кода

Функциональность этих процедур полностью сохраняется через параметризацию оригинальных процедур ЗагрузитьОбъекты и ПрочитатьНаСервере с параметром "РЕПО".

5. Преимущества решения

  • Обратная совместимость: Существующий код продолжит работать без изменений
  • Единая точка изменений: Все изменения в одном месте
  • Упрощение поддержки: Меньше кода для поддержки
  • Снижение рисков: Невозможна рассинхронизация логики
  • Улучшение читаемости: Понятная структура с явными параметрами

6. Примечания

  • Процедура ОбновитьПартнера НЕ является дублем СоздатьОбъекты (совпадение ~5-10%)
  • Она решает другую задачу (обновление существующих сделок vs создание новых) и будет оставлена без изменений
  • Все изменения будут помечены комментариями // IMAPPS-PARAM: REPO для удобства поиска
