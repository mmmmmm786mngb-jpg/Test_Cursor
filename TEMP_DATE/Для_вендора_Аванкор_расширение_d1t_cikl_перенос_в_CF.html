Расширение d1t_cikl: назначение и перенос в оригинальную конфигурацию

Для вендора Аванкор. Конфигурация: Доверительное управление, база 1.5.27.0. Документ сопровождает расширение d1t_cikl при передаче (задача ASP-196537). Реализован только пункт 1 оптимизации: перенос цикла регламентных операций с клиента на сервер.

1. Зачем сделано

В базовой конфигурации формирование регламентных операций закрытия периода (утренние операции) выполнялось так:

  • В модуле формы справочника РегламентныеПериоды процедура в цикле по договорам вызывала серверную процедуру формирования документов для каждого договора.
  • На 3 500+ договоров это давало тысячи серверных вызовов с клиента (по замерам — 9,26% времени) и долгое ожидание без отображения прогресса.

Расширение d1t_cikl переносит цикл на сервер: запуск выполняется через длительную операцию (фоновое задание), тело операции и вызов СформироватьДокументыЗакрытияПериода по каждому договору выполняются в модуле менеджера справочника РегламентныеПериоды; в форме остаются только запуск задания, отслеживание прогресса и обработка результата.

3. Как решено

  • Форма: вместо цикла с серверными вызовами вызывается длительная операция (фоновое задание). Процедура reg_m_СформироватьРегламентныеОперации запускает задание; функция СформироватьРегламентныеОперацииНаСервере формирует параметры и возвращает ссылку на задание. Процедуры НачатьОтслеживаниеЗадания, ОбработатьРезультатЗадания, ЗавершитьОбработкуПослеУспехаНаКлиенте, ПоказатьПредупреждениеОбОшибке обеспечивают отслеживание прогресса и обработку результата.
  • Модуль менеджера: процедура СформироватьРегламентныеОперацииНаСервере (тело длительной операции) в цикле по договорам вызывает СформироватьДокументыЗакрытияПериода. Цикл выполняется на сервере без тысяч обращений с клиента.

Цепочка длительной операции (создание задания, передача параметров, выполнение тела) использует механизмы базовой конфигурации (ФоновыеЗаданияСервер, ПланРегламентныхОперацийДУ и т.д.); в d1t_cikl изменены только форма и модуль менеджера справочника РегламентныеПериоды.

4. Как перенести в оригинальную конфигурацию (CF)

Важно. При переносе логики из d1t_cikl в CF скопировать код из соответствующих модулей расширения в те же объекты CF. Имена процедур и функций сохранить (в т.ч. reg_m_СформироватьРегламентныеОперации или заменить на имя, принятое в CF).

Что перенести:

  • Справочник.РегламентныеПериоды, форма РегламентныйПериод: из d1t_cikl/Catalogs/РегламентныеПериоды/Forms/РегламентныйПериод/Ext/Form/Module.bsl — процедуры и функции формы (reg_m_СформироватьРегламентныеОперации, СформироватьРегламентныеОперацииНаСервере (функция), НачатьОтслеживаниеЗадания, ОбработатьРезультатЗадания, ЗавершитьОбработкуПослеУспехаНаКлиенте, ПоказатьПредупреждениеОбОшибке). При необходимости скорректировать вызовы длительной операции под API CF.
  • Справочник.РегламентныеПериоды, модуль менеджера: из d1t_cikl/Catalogs/РегламентныеПериоды/Ext/ManagerModule.bsl — процедуры СформироватьРегламентныеОперацииНаСервере (процедура), СформироватьДокументыЗакрытияПериода. Убедиться, что вызов фонового задания и передача параметров соответствуют CF.
  • Очистка кода при переносе: перед внесением в CF удалить области, помеченные для удаления (например, #Область УДАЛИ_МЕНЯ ... #КонецОбласти). Комментарии разработки и маркеры IMAPPS-... оставлять.
