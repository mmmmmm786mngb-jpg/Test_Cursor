ACCOUNTING-17091. Analiz postanovki zadachi (TO BE)

Отправка брокерских отчетов в спец. депозитарии через транзит ИШ. По каждому пункту TO BE: корректность требования, способ реализации, ссылки на конфигурации ИЦ и ДЕПО.

Источники и конфигурации

  • 1С ИЦ (SBB_Broker): C:\1c\Cursor_1c\WORK\SBB_Broker — отчёты клиентов, регистр ОтчетыКлиентов, рассылка, форма ОтчетКлиентаNew.
  • 1С ДЕПО (SBB_Depo): C:\1c\Cursor_1c\WORK\SBB_Depo — W-пакеты, winf, ТехническаяОперация, ИсходящийПакет, обработка квитанций.

Условия отбора договоров (из задачи): ДоговорыКонтрагентов.ВидДУ = ПИФ, ВидДоговора = «Договор обслуживания на финансовых рынках», ДатаОкончанияДействия не заполнена.

TO BE 1 Регламентное задание «Рассылка отчетов в спец. деп» (1С ИЦ)

Требуемое

На стороне 1С ИЦ добавить РЗ с расписанием — каждый рабочий день в 19:00 (время настраиваемое).

Анализ корректности

  • Корректно. В SBB_Broker уже есть много регламентных заданий (ScheduledJobs); механизм стандартный.
  • Расписание «рабочие дни 19:00» — типично реализуется через РасписаниеЗадания (поддерживает дни недели и время).

Способ реализации

Предложение в задаче: добавить регламентное задание «Рассылка отчетов в спец. деп» с расписанием — каждый рабочий день в 19:00; время можно менять и настраивать. Конкретный тип объекта (ScheduledJob), имя и способ настройки времени в постановке не указаны.

Моё предложение:

  1. Создать новый объект метаданных ScheduledJob с именем, например, РассылкаОтчетовВСпецДеп; метод выполнения — вызов процедуры общего модуля или обработки, в которой реализована логика TO BE 4 (сверка регистров, получение файлов, winf, вызов веб-сервиса ДЕПО).
  2. Расписание: использовать стандартное расписание регламентного задания — «Ежедневно» с временем 19:00; для отбора только рабочих дней — либо указать дни недели (Пн–Пт), либо завести реестр рабочих дней и в коде метода проверять дату перед запуском.
  3. Настраиваемое время: вынести время запуска в константу (например, «ЧасРассылкиОтчетовВСпецДеп») или в параметр регистра сведений/настроек; в методе РЗ читать это значение и при необходимости проверять «текущее время ≈ время запуска» или использовать расписание с подстановкой значения из константы при сохранении расписания.

Где смотреть аналоги в ИЦ: SBB_Broker\ScheduledJobs\ — любое РЗ с расписанием (напр. АвтоматическоеВыполнениеЗадач, запуск обменов).

TO BE 2 Регистр сведений «Спец. депозитарии клиентов» (1С ИЦ)

Требуемое

Структура: Период, Клиент, Договор, Спец. депозитарий (наименование), Код в НРД, Флаг активности. Заполнение для существующих клиентов — внешней обработкой по xls. На втором этапе — загрузка из СУДК при регистрации клиента.

Анализ корректности

  • Корректно. В SBB_Broker нет регистра с именем «Спец. депозитарии клиентов» и указанной структурой.
  • Есть смежные объекты: КлиентыСЗапросомПоБалансовойСтоимостиЦБВСпецДепе, СпецПолномочияПоРаспоряжениюИОсуществлениюПравНаЦБ — другие цели, не «код спец депа + активность» для рассылки отчётов.
  • Период в качестве измерения — хранит историю при смене спец депа; «последняя запись с Флагом активности = Истина» определяет текущий спец деп.

Способ реализации

Предложение в задаче: новый регистр сведений «Спец. депозитарии клиентов» со структурой: Период, Клиент, Договор, Спец. депозитарий (наименование), Код в НРД, Флаг активности. Заполнение для существующих клиентов — внешней обработкой по xls от бизнеса. На втором этапе — отдельная задача на загрузку данных о спец депе из СУДК при регистрации/обновлении клиента. Логика при смене спец депа: новая запись с новым соответствием и флагом активности (новой датой), у старой записи флаг снимается.

Моё предложение:

  1. Создать регистр сведений периодическим (запись по дате), режим записей — «Подчинение регистратору» не использовать; измерения: Период (Дата), Клиент (СправочникСсылка), Договор (СправочникСсылка); ресурсы/реквизиты: СпецДепозитарийНаименование (Строка), КодВНРД (Строка), Активность (Булево). Имена — по стандартам конфигурации.
  2. «Текущий» спец деп по клиенту/договору: срез последних на дату с отбором Активность = Истина либо запрос «максимум Период по (Клиент, Договор) где Активность = Истина».
  3. При смене спец депа: перед записью новой строки обновить предыдущую запись по (Клиент, Договор), установив Активность = Ложь; затем записать новую строку с новой датой Период и Активность = Истина. Либо одна процедура «УстановитьСпецДепозитарий(Клиент, Договор, Наименование, КодВНРД)», внутри — снятие активности у старых и запись новой.
  4. Внешняя обработка загрузки из xls: отдельная обработка с таблицей соответствия колонок файла полям регистра (Период, Клиент, Договор, СпецДепозитарийНаименование, КодВНРД, Активность); поиск Клиента/Договора по коду или наименованию; пакетная запись. Загрузку из СУДК не трогать в первой итерации — оставить отдельной задачей.

TO BE 3 Признак «Официальный» на форме отчёта (1С ИЦ)

Требуемое

На форму отчёта добавить признак (Официальный). При ручном формировании через ОтчетКлиентаNew с установленным признаком — запись в РС «Отчеты клиентов» с соответствующим флагом.

Анализ корректности

  • Корректно. В РС ОтчетыКлиентов (SBB_Broker) уже есть реквизит Официальный.
  • В Reports\ОтчетКлиентаNew\Ext\ManagerModule.bsl процедура СформироватьОтчет(Отчет, ИдентификаторФормы, КоличествоОтчетов, ЭтоОфициальныйОтчет = Ложь) — 4-й параметр по умолчанию Ложь.
  • Форма ОтчетКлиентаNew\ФормаОтчета вызывает Отчеты.ОтчетКлиентаNew.СформироватьОтчет(Отчет, УникальныйИдентификатор, КоличествоОтчетов) без 4-го параметра — поэтому при ручном запуске всегда Официальный = Ложь.
  • Рассылка: в модулях рассылки (общий модуль РассылкаОтчетов, отчёт ОтчетКлиентаNewДляРассылки и т.п.) проверяется отбор «только официальный» — если у клиента настройка «только официальный», уточнённый (неофициальный) отчёт не направляется.

Способ реализации

Предложение в задаче: на форму отчёта добавить признак (Официальный). Если пользователь формирует отчёт вручную через форму ОтчетКлиентаNew и устанавливает признак «Официальный», запись в регистре «Отчеты клиентов» должна создаваться с соответствующим флагом. Отмечено влияние на существующий механизм рассылок (настройка «только официальный отчёт»).

Моё предложение:

  1. На форму ОтчетКлиентаNew\ФормаОтчета: добавить реквизит формы Официальный (Булево), по умолчанию Ложь; вывести на форму элемент «Флажок» с привязкой к этому реквизиту, подпись «Официальный» (или «Зарегистрировать как официальный отчёт»).
  2. В коде формы в месте вызова Отчеты.ОтчетКлиентаNew.СформироватьОтчет(...) передавать четвёртым параметром значение реквизита Официальный. Аналогично в вызове, который запускает фоновое задание, включить Официальный в структуру параметров (ПараметрыОтчета).
  3. В модуле менеджера отчёта в СформироватьОтчетВФоне при извлечении параметров из ПараметрыОтчета читать признак (напр. ПараметрыОтчета.Официальный) и передавать его 4-м параметром в СформироватьОтчет. По умолчанию, если ключа нет, считать Ложь.
  4. Обойти все вызовы СформироватьОтчет/СформироватьОтчетВФоне (форма отчёта, БП «Открытие дня» и др.): там, где отчёт считается официальным (БП), явно передавать 4-й параметр Истина; в форме — всегда передавать значение с формы. Механизм рассылки не менять — он уже опирается на реквизит Официальный в РС ОтчетыКлиентов.

TO BE 4 Обработка сверки и отправки в спец деп (1С ИЦ)

Требуемое

Обработка по РЗ: сверка РС «Спец. депозитарии клиентов» с РС «Отчеты клиентов». Для каждой последней записи по клиенту из «Спец. депозитарии клиентов» найти последнюю запись в «Отчеты клиентов» за текущий день с признаком Официальный. Из хранилища взять файлы отчёта (во всех форматах), преобразовать имя (договор + период, без кириллицы), сформировать winf.xml, через обмен ИЦ–ДЕПО передать файлы и инициировать формирование исходящего пакета на стороне ДЕПО.

Анализ корректности

  • Корректно. В ИЦ есть хранилище отчётов (РС ОтчетыКлиентов, поле Данные / хранилище), модуль РассылкаОтчетов и обработка «Выгрузка файлов сформированных отчётов клиента» — есть аналоги получения файлов и форматов.
  • Обмен ИЦ–ДЕПО: в задаче указано «через существующий веб-сервис, по аналогии с другими документами». В SBB_Broker есть WebServices/HTTPServices — нужно определить, как именно передаются документы в «интеграционный шлюз» и добавить тип сообщения «отчёт в спец деп» (winf + файлы).
  • Ограничение: размер пакета не более 200 МБ, количество ТЭД не более 100 — нужен учёт при группировке (задача говорит: группировать по спец депу не требуется, т.е. каждый клиент — отдельная отправка).

Способ реализации

Предложение в задаче: добавить обработку в 1С ИЦ, которая по новому регламенту сверяет РС «Спец. депозитарии клиентов» с РС «Отчеты клиентов»: для каждой последней по клиенту записи из первого регистра искать последнюю запись во втором за текущий день с признаком «Официальный»; для найденной записи доставать файл из хранилища во всех форматах; преобразовывать имя файла (договор + период, без кириллицы, пример «1003746 29.01.2026-29.01.2026»); формировать winf.xml по шаблону из раздела «Отправка пакетов через ИШ»; с помощью обмена ИЦ–ДЕПО (существующий веб-сервис, по аналогии с другими документами) передавать winf и файлы и инициировать формирование исходящего пакета на стороне ДЕПО. На втором этапе — ручной запуск с выбором записи из «Отчеты клиентов» для переотправки. Упомянуты аналоги: РассылкаОтчетов, обработка «Выгрузка файлов сформированных отчетов клиента».

Моё предложение:

  1. Реализовать в виде обработки (или выносимой логики в общий модуль с вызовом из обработки и из РЗ): основной режим — запуск по регламенту; на втором этапе — форма с выбором записи РС «Отчеты клиентов» (клиент, дата формирования, период) для ручной переотправки одного отчёта.
  2. Алгоритм: (1) Срез последних записей РС «Спец. депозитарии клиентов» на текущую дату с Активность = Истина, отбор по условиям задачи (ПИФ и т.д.) при необходимости. (2) Для каждой пары (Клиент, Договор) запрос к РС «Отчеты клиентов»: ДатаФормирования = текущий день, Официальный = Истина, отбор по Клиенту/Договору (или КодПортфеля — уточнить по структуре регистра), взять последнюю запись. (3) По полученным записям регистра получить из хранилища (реквизит Данные или отдельное хранилище) файлы во всех сохранённых форматах — по аналогии с РассылкаОтчетов и обработкой выгрузки для КМ.
  3. Имя файла: строго по задаче — номер договора (код договора) + пробел + период в формате «ДД.ММ.ГГГГ-ДД.ММ.ГГГГ», без кириллицы; при необходимости транслитерация/замена символов. Расширения — .pdf, .xlsx, .xml в соответствии с фактически хранимыми форматами.
  4. Формирование winf.xml — см. TO BE 5; вызывать общую процедуру/макет из этой же обработки (модуля).
  5. Обмен ИЦ–ДЕПО: использовать существующий веб-сервис ДЕПО (FunctionalElectronicDocuments или новую операцию/сервис для отчётов в спец деп). Передавать: winf (строка/XML), список файлов (бинарные данные или base64). На стороне ДЕПО по приёму — создание ТехническаяОперация (комментарий «Транзитный пакет в спец. депозитарий»), ИсходящийПакет, запись в РС состояний и формирование папки/файлов в OUTBOX. Ограничения из задачи (200 МБ, 100 ТЭД) учитывать: одна отправка = один клиент/договор, без группировки по спец депу.

TO BE 5 Формирование сопроводительного файла winf.xml (1С ИЦ)

Требуемое

На стороне 1С ИЦ настроить формирование winf.xml по схеме и примерам из задачи (COVERING_LETTER, ORIGINATOR, RECIPIENT, SERVICE_MARKS, DOC с TRZT, ORIGINAL_FILE_NAME).

Анализ корректности

  • Корректно. Структура winf для транзитных отчётов в задаче отличается от winf для раскрытий (в ДЕПО шаблон Документ.РаскрытиеСпискаВладельцев — другой LETTER_TYPE/DOC_TYPE и контекст).
  • В ДЕПО уже есть Documents\РаскрытиеСпискаВладельцев\Templates\ИсходящийШаблонТранзитWINF и ПараметрыТранзитаWINF в ManagerModule — но это для документа РаскрытиеСпискаВладельцев (ORIGINATOR/RECIPIENT из организации и инициатора). Для отчётов в спец деп: отправитель — код ИЦ (MC...), получатель — Код в НРД спец депа из регистра «Спец. депозитарии клиентов».

Способ реализации

Предложение в задаче: на стороне 1С ИЦ настроить формирование сопроводительного файла для отчёта (winf.xml); схема, описание и пример файла — в разделе «Отправка пакетов через ИШ» (COVERING_LETTER, ORIGINATOR, RECIPIENT, SERVICE_MARKS, DOC с TRZT, ORIGINAL_FILE_NAME и атрибуты по таблице).

Моё предложение:

  1. Реализовать в ИЦ в общем модуле или в модуле обработки рассылки в спец деп: либо макет с подстановками (шаблон winf с плейсхолдерами [ORIGINATOR], [RECIPIENT], [LETTER_ID] и т.д.), либо последовательная запись XML (ЗаписьXML / сериализация структуры). Параметры: код отправителя ORIGINATOR (CONTRAGENT_CODE ИЦ в НРД — константа или настройка), код получателя RECIPIENT (КодВНРД из записи РС «Спец. депозитарии клиентов»), LETTER_ID (уникальный GUID пакета), CONTR_LETTER_ID (номер тех. операции с стороны ДЕПО или временный идентификатор до создания тех. операции), LETTER_TYPE=NDC0STND, CREATE_TIME — DATE в формате dd.mm.yyyy и TIME hh:nn:ss; корень COVERING_LETTER с атрибутами TRANSIT="YES", PROCESSING_MODE="LIVE", STATE="ORIG_TO_NDC".
  2. Для каждого приложенного файла отчёта — один элемент DOC с атрибутами STORE_IN_NDC="YES", ENCRYPTED="YES", DELIVERY_TIMED_OUT="NO", TRANSFER_AGENT_CONTRACT="NO", дочерний DOC_TYPE=TRZT, ORIGINAL_FILE_NAME — имя файла без кириллицы (как сформировано в TO BE 4).
  3. Форматы даты/времени — строго по задаче: DATE — dd.mm.yyyy, TIME — hh:nn:ss. Имена файлов в ORIGINAL_FILE_NAME — только латиница/цифры/точка/пробел/дефис, при необходимости транслит или замена кириллицы на коды.

TO BE 6 Доработка механизма W-пакетов в OUTBOX (1С ДЕПО)

Требуемое

На стороне 1С ДЕПО доработать существующий механизм создания исходящих W-пакетов в папке OUTBOX для отправки файлов отчётов в адрес каждого спец депозитария.

Анализ корректности

  • Корректно. В SBB_Depo процедура СформироватьИсходящийПакетВФайловыйШлюз находится в DataProcessors\ЭкспортПорученийВЛуч\Ext\ManagerModule.bsl. Существует вызов из обработок (РаскрытиеСписковВладельцевFCDR_2017_02, ЭкспортПорученийВРДЦ и др.) — формируются папки, файлы, winf.
  • По задаче: для транзитного пакета тип ЭД = TRANS, первый символ признак = W. Имя папки, напр.: W1610001 (16 января, 10001). Месяц в шестнадцатеричном виде (1–9, A, B, C).
  • В папку поместить 4 файла: 1–3 — отчёт (pdf, xml, xls), 4 — winf.xml.

Способ реализации

Предложение в задаче: на стороне 1С ДЕПО доработать существующий механизм по созданию исходящих W-пакетов в папке OUTBOX интеграционного шлюза для отправки файлов отчётов в адрес каждого специализированного депозитария; подробности — в разделе «Отправка пакетов через ИШ» (тип ЭД TRANS, признак W, имя папки например W1610001, месяц в шестнадцатеричном виде; в папку поместить файлы отчёта в форматах и winf.xml).

Моё предложение:

  1. Не дублировать логику, а расширить использование СформироватьИсходящийПакетВФайловыйШлюз в ЭкспортПорученийВЛуч: добавить перегрузку процедуры или отдельную экспортную процедуру (напр. СформироватьИсходящийПакетТранзитОтчетВСпецДеп), у которой входные параметры: готовый текст winf.xml, массив файлов (ДвоичныеДанные или пути), код получателя в НРД (RECIPIENT), идентификатор (GUID) для LETTER_ID, номер/идентификатор для CONTR_LETTER_ID. TO BE 8 Чтение и обработка квитанций TRNOC/TRNRC (1С ДЕПО)

Требуемое

На стороне 1С ДЕПО читать и обрабатывать квитанции. На первом этапе — доработать обработку TRNOC и TRNRC с ошибками, чтобы не «падать» в ошибку. На втором — заполнение статусов и регистра по требованиям.

Анализ корректности

  • Корректно. Чтение W-пакетов и обработка квитанций — в DataProcessors\ФайлыНРД\Ext\ObjectModule.bsl и DataProcessors\ЗагрузкаКДИзДепозитария\Ext\ObjectModule.bsl. По задаче квитанции определяются как FCDR_2017_02 (раскрытия), но транзитные пакеты отчётов будут с LETTER_TYPE NDC0STND и STATE NDC_TO_ORIG / RECIP_TO_NDC — нужно распознавать такие пакеты и не считать их раскрытием.
  • Обнаружен баг в коде ДЕПО: в процедуре СтатусКвитанцииВДокументы (ФайлыНРД, около строки 268) вызывается РСВОбъект = ТехническаяОперация.ДокументОснование.ПолучитьОбъект(); без проверки типа основания. Для документа РаскрытиеСпискаВладельцев — это документ, у него есть ПолучитьОбъект(). Для транзита отчётов в спец деп основанием может быть пустая ссылка или другой тип; вызов ПолучитьОбъект() даёт ошибку «Значение не является значением объектного типа (ПолучитьОбъект)».
