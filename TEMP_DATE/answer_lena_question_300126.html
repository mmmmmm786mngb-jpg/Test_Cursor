Ответ на открытый вопрос к разработчику и описание доработки «Признак Официальный»

Задача: ACCOUNTING-17091. Конфигурация: SBB_Broker (C:\1c\Cursor_1c\WORK\SBB_Broker). Анализ кода 1С. 30.01.2026.

1. Открытый вопрос к разработчику (повторная проверка)

1.1. Вопрос 1: По умолчанию при ручном формировании «Официальный» = Ложь?

Да, верно. При формировании отчета клиента через форму ОтчетКлиентаNew вручную в регистр сведений «Отчеты клиентов» по умолчанию записывается Официальный = Ложь.

Детальная проверка по коду

А. Модуль менеджера отчета ОтчетКлиентаNew (ManagerModule.bsl)

Процедура СформироватьОтчет(Отчет, ИдентификаторФормы, КоличествоОтчетов, ЭтоОфициальныйОтчет = Ложь) Экспорт

Четвертый параметр ЭтоОфициальныйОтчет объявлен со значением по умолчанию Ложь.

Б. Форма отчета (ФормаОтчета, Module.bsl) — прямой вызов (без фона)

Отчеты.ОтчетКлиентаNew.СформироватьОтчет(Отчет, УникальныйИдентификатор, КоличествоОтчетов);

Передаются только три аргумента. Четвертый не передается → используется значение по умолчанию Ложь.

В. Модуль менеджера — фоновое формирование (СформироватьОтчетВФоне)

КоличествоОтчетов = 0; СформироватьОтчет(Отчет, ИдентификаторФормы, КоличествоОтчетов);

Также вызывается с тремя параметрами → Официальный = Ложь и при формировании в фоне из формы.

Г. Запись в регистр (ManagerModule.bsl)

Процедура ЗаписатьОтчетВРегистр(Отчет, СтруктураРезультата, ИдентификаторФормы, ЭтоОфициальныйОтчет) ... Запись.Официальный = ЭтоОфициальныйОтчет; Запись.Записать(); КонецПроцедуры

Значение ЭтоОфициальныйОтчет без изменений попадает в реквизит записи регистра Официальный.

Итог по вопросу 1: Все точки входа с формы (прямой и фоновый вызов) не передают четвертый параметр → в регистр всегда записывается Официальный = Ложь при ручном формировании.

1.2. Вопрос 2: Признак «Официальный» проверяется в модуле «РассылкаОтчетов»?

Да, верно, с уточнением: проверка выполняется не в теле общего модуля «РассылкаОтчетов», а в отчете ОтчетКлиентаNewДляРассылки, который используется подсистемой рассылки для выборки отчетов из регистра «Отчеты клиентов». Параметр рассылки ТолькоОфициальный (синоним «Отправлять только официальный») задает фильтр по полю Официальный регистра.

Детальная проверка по коду

А. Отчет ОтчетКлиентаNewДляРассылки (ManagerModule.bsl)

В тексте запроса к регистру «Отчеты клиентов»:

И ВЫБОР КОГДА &ТолькоОфициальный ТОГДА ОтчетыКлиентов.Официальный = &ТолькоОфициальный ИНАЧЕ ОтчетыКлиентов.Официальный ИЛИ ОтчетыКлиентов.ИдентификаторФормы = &ИдентификаторОтбора КОНЕЦ

При ТолькоОфициальный = Истина в рассылку попадают только записи с Официальный = Истина. Ручные (уточненные) отчеты с Официальный = Ложь при такой настройке не отбираются.

Б. Установка параметра

Запрос.УстановитьПараметр("ТолькоОфициальный", ОтчетОбъект.ТолькоОфициальный);

Значение берется из реквизита отчета для рассылки (настройки рассылки/получателя).

В. Дополнительное место: ФормированиеОтчетовНаСервере

В общем модуле ФормированиеОтчетовНаСервере в запросе к регистру «Отчеты клиентов» также используется фильтр по официальности (выкладка в СЭД):

ИЗ РегистрСведений.ОтчетыКлиентов КАК ОтчетыКлиентов ГДЕ ОтчетыКлиентов.Официальный И ОтчетыКлиентов.ДатаФормирования МЕЖДУ &НачалоПериода И &КонецПериода

То есть в выкладке в СЭД участвуют только отчеты с Официальный = Истина. Ручные отчеты с Официальный = Ложь в этот процесс не попадают.

Итог по вопросу 2: Признак «Официальный» проверяется в механизме рассылки (отчет ОтчетКлиентаNewДляРассылки, параметр ТолькоОфициальный) и в выкладке в СЭД (ФормированиеОтчетовНаСервере). Общий модуль «РассылкаОтчетов» вызывает отчет для рассылки, в котором и выполняется эта проверка.

2. Доработка: на форму отчета добавить признак (Официальный)

2.1. Цель задачи

  • Дать пользователю возможность при ручном формировании отчета через форму ОтчетКлиентаNew явно указать, что отчет считается официальным.
  • При установленном признаке «Официальный» запись в регистр сведений «Отчеты клиентов» должна создаваться с Официальный = Истина.
  • Обеспечить согласованность с существующим механизмом рассылок: если у клиента включена настройка «Отправлять только официальный», то такие ручные отчеты должны попадать в рассылку наравне с отчетами, сформированными в рамках БП «Открытие дня».
  • Уточненные (корректировочные) отчеты, которые БО формирует вручную, при необходимости смогут помечаться как официальные и тогда не будут отсекаться рассылкой для получателей с настройкой «только официальный».

2.2. Текущее состояние

  • В отчете ОтчетКлиентаNew реквизита Официальный нет (есть Документооборот, СохранятьОтчеты и др.).
  • На форме есть группа с признаками «Сохранять отчеты», «Зарегистрировать в базе документооборота» (Документооборот), «Выводить печать и подпись» и т.д.; признака «Официальный» нет.
  • Регистр сведений «Отчеты клиентов» уже содержит реквизит Официальный (булево), он заполняется только из параметра процедуры СформироватьОтчет.
  • Отчет для рассылки ОтчетКлиентаNewДляРассылки уже использует параметр ТолькоОфициальный и фильтрует по ОтчетыКлиентов.Официальный — доработка только на стороне формы и отчета ОтчетКлиентаNew.

2.3. Способ реализации

Шаг 1. Метаданные отчета ОтчетКлиентаNew

  • Добавить реквизит отчета: Официальный, тип Булево, значение по умолчанию Ложь.
  • Синоним, например: «Официальный» (или «Считать отчет официальным»).

Шаг 2. Форма отчета (ФормаОтчета)

  • Добавить на форму элемент управления: флажок (CheckBoxField), DataPath = Отчет.Официальный.
  • Расположение: логично рядом с группой «Зарегистрировать в базе документооборота» (ГруппаДокументооборот), т.к. оба признака влияют на то, как отчет учитывается в СЭД и рассылке.
  • Подсказка: пояснить, что при установке отмеченный отчет будет учитываться в рассылке для получателей с настройкой «только официальный».
  • При необходимости: показывать элемент только при включенном «Документооборот» (аналогично «Подпись клиента») или всегда — по решению заказчика.

Шаг 3. Модуль формы (ФормаОтчета, Module.bsl)

  • В процедуре/функции СформироватьОтчетНаСервере: при вызове Отчеты.ОтчетКлиентаNew.СформироватьОтчет(...) передавать четвертый параметр Отчет.Официальный.
  • В структуру ПараметрыОтчета (используется при фоновом формировании) добавить поле Официальный = Отчет.Официальный, чтобы фоновый сценарий тоже получал актуальное значение.

Шаг 4. Модуль менеджера отчета (ManagerModule.bsl)

  • В процедуре СформироватьОтчетВФоне: из ПараметрыОтчета читать значение «Официальный» и передавать его четвертым параметром в СформироватьОтчет(..., ЭтоОфициальныйОтчет). Сейчас вызов с тремя параметрами — добавить четвертый из параметров фоновой задачи.

Шаг 5. Настройки по умолчанию (по желанию)

  • В процедурах сохранения настроек формы (СтруктураОбщихПараметров для основной настройки, БП «Открытие дня», БП «Открытие дня иностранные рынки») при необходимости добавить Официальный, чтобы значение сохранялось/восстанавливалось вместе с другими параметрами отчета. Для БП это не обязательно, т.к. там значение «Официальный» задается кодом (Истина), а не формой.

Изменений в регистре сведений «Отчеты клиентов», в отчете «ОтчетКлиентаNewДляРассылки» и в общем модуле «РассылкаОтчетов» не требуется: логика фильтрации по «Официальный» уже реализована.

2.4. Мнение о возможности реализации

Реализовать доработку возможно без рисков для существующей логики.

  • Четвертый параметр ЭтоОфициальныйОтчет в СформироватьОтчет и запись в регистр уже есть; нужно только «подвести» к нему значение с формы.
  • Добавление реквизита отчета и элемента формы — типовая операция в 1С; цепочка форма → ПараметрыОтчета → СформироватьОтчет/СформироватьОтчетВФоне → ЗаписатьОтчетВРегистр прослеживается однозначно.
  • Рассылка и выкладка в СЭД уже опираются на поле «Официальный» регистра; после появления на форме признака «Официальный» ручные отчеты с этой пометкой автоматически начнут участвовать в отборе там, где требуется только официальный отчет.
  • Рекомендуется: один раз проверить сценарии — ручное формирование с включенным «Документооборот» и установленным «Официальный», затем проверка рассылки для получателя с настройкой «Отправлять только официальный» и при необходимости — выкладка в СЭД.

Важно: При фоновом формировании (СформироватьОтчетВФоне) в текущей реализации в вызов СформироватьОтчет не передается четвертый параметр. Поэтому при доработке обязательно передавать Официальный из ПараметрыОтчета в СформироватьОтчетВФоне, иначе при длительном формировании значение с формы не попадет в регистр.

4. Итоговые выводы

  1. При ручном формировании через форму ОтчетКлиентаNew в регистр «Отчеты клиентов» по умолчанию записывается Официальный = Ложь (подтверждено по всем точкам вызова: форма и СформироватьОтчетВФоне).
  2. Признак «Официальный» проверяется в механизме рассылки (отчет ОтчетКлиентаNewДляРассылки, параметр ТолькоОфициальный) и в выкладке в СЭД (ФормированиеОтчетовНаСервере). Общий модуль «РассылкаОтчетов» использует отчет для рассылки, в котором и выполняется эта проверка.
  3. Доработка «на форму отчета добавить признак (Официальный)» целесообразна и реализуема: добавление реквизита отчета, элемента на форму и передача значения в СформироватьОтчет / СформироватьОтчетВФоне закрывает задачу без изменения регистра и логики рассылки.
