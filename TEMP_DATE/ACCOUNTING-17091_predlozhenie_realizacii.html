ACCOUNTING-17091

Предложение по реализации: отправка отчётов в спец. депозитарии

Общая схема

ИЦ Регистр + Отчёты
Формируем «пакет»
➡
COM / WS ХранилищеЗначений
Передаём в Депо
➡
Депо ТехОперация + W-пакет
winf + файлы
➡
ИШ НРД Транзит
Квитанции

Сторона ИЦ (SBB_Broker)

1. Регистр сведений «Спец. депозитарии клиентов»

Поле Тип Назначение
Период Дата Для истории изменений
Клиент Справочник.Контрагенты Измерение
Договор Справочник.ДоговорыКонтрагентов Измерение (опц.)
НаименованиеСпецДепа Строка Для информации
КодВНРД Строка Код получателя (RECIPIENT)
Активен Булево Текущий спец. деп клиента

2. Флаг «Официальный» в отчёте

В форме ОтчетКлиентаNew — чекбокс; при формировании передаётся в СформироватьОтчет(..., ЭтоОфициальныйОтчет), записывается в регистр ОтчетыКлиентов.Официальный.

3. Регламентное задание + функция «Получить пакет к отправке»

РЗ (2 раза в день, рабочие дни) вызывает процедуру, которая:

  1. Запрашивает активных клиентов из регистра «Спец. депозитарии клиентов»
  2. Для каждого находит официальный отчёт за текущий день в регистре «Отчеты клиентов»
  3. Формирует «пакет» — структура:
    • КодПолучателяНРД — из регистра спец. депов
    • НомерДоговора — для имени файла
    • ПериодОтчета — для имени файла
    • ФайлыОтчета — массив структур {ИмяФайла, ДвоичныеДанные} (pdf, xml, xls)
  4. Упаковывает пакет в ХранилищеЗначения (или структуру)
  5. Вызывает функцию отправки в Депо
// Пример структуры пакета
Пакет = Новый Структура;
Пакет.Вставить("КодПолучателяНРД", "REG044100000");
Пакет.Вставить("НомерДоговора", "1003746");
Пакет.Вставить("НачалоПериода", '20260129');
Пакет.Вставить("КонецПериода", '20260129');
Пакет.Вставить("Файлы", МассивФайлов); // [{Имя, Данные}, ...]

4. Функция отправки в Депо

Два варианта:

  • COM-соединение — вызов процедуры общего модуля Депо напрямую
  • Веб-сервис — расширение FunctionalElectronicDocuments или новый сервис

Передаём: ХранилищеЗначения с пакетом (или XDTO-объект для WS).

Сторона Депо (SBB_Depo)

5. Приём пакета и формирование W-пакета

Функция принимает пакет от ИЦ и выполняет:

  1. Создаёт ТехническуюОперацию с признаком/комментарием «Отчёт в спец. депозитарий» (или новый документ по аналогии с РСВ — на выбор)
  2. Формирует winf.xml:
    • ORIGINATOR — код организации в НРД (есть в Депо)
    • RECIPIENT — из пакета (КодПолучателяНРД)
    • LETTER_ID — GUID ТехОперации
    • CONTR_LETTER_ID — номер ТехОперации
    • SUBJECT — «NTED#report» (отличие от РСВ)
    • DOC — для каждого файла (TRZT, ORIGINAL_FILE_NAME)
  3. Создаёт папку W-пакета (W + dd + месяц_hex + номер) в OUTBOX
  4. Записывает файлы: winf.xml + файлы отчёта
  5. Создаёт ИсходящийПакетВФайловыйШлюз, запись в РС «Состояния документов в файловом шлюзе»

По сути — аналог СформироватьИсходящийПакетВФайловыйШлюз, но с внешними данными (winf и файлы приходят/формируются, а не из РСВ).

6. Квитанции

Существующий механизм в ФайлыНРД:

  • Поиск ТехОперации по LETTER_ID — уже работает
  • Запись комментария в ТехОперацию — уже работает
  • Обновление статуса ИсходящегоПакета и РС — уже работает

Доработка: в СтатусКвитанцииВДокументы не вызывать ПолучитьОбъект() для ДокументОснование, если это не РаскрытиеСпискаВладельцев (или пустое). Можно отличать по SUBJECT = NTED#report в winf.

Плюсы и нюансы предложения

✅ Плюсы

  • Максимальное переиспользование существующего механизма W-пакетов
  • Квитанции уже работают (минимум доработок)
  • Чёткое разделение: ИЦ готовит «что отправить», Депо — «как отправить»
  • ХранилищеЗначения — простая передача бинарных данных
  • ТехОперация с признаком — не нужен новый документ

⚠ Нюансы

  • COM-соединение требует доступности сервера Депо из ИЦ
  • Веб-сервис — нужно передавать бинарные данные (base64)
  • Winf: часть данных из ИЦ, часть из Депо — нужно определить, где формировать
  • Проверить: не сломается ли обработка квитанций для других типов пакетов

Где формировать winf?

Вариант A: В Депо (рекомендуется). ИЦ передаёт только адресацию (КодПолучателяНРД) и файлы. Депо знает код организации (ORIGINATOR), генерирует GUID и номер ТехОперации, формирует winf целиком. Аналогия с РСВ — winf формируется в момент создания W-пакета.

Вариант B: В ИЦ. Тогда ИЦ должен знать код организации в НРД, а Депо должен вернуть номер ТехОперации заранее (два вызова) или ИЦ сам генерирует GUID и передаёт его.

Вариант A проще и соответствует текущей архитектуре.

Итоговый план

ИЦ

1. Регистр «Спец. депозитарии клиентов» + формы
2. Флаг «Официальный» на форме отчёта
3. Функция «ПолучитьПакетДляОтправкиВСпецДеп» — выборка + упаковка
4. Функция «ОтправитьПакетВДепо» — COM/WS
5. РЗ «Рассылка отчётов в спец. деп» — 2 раза в день

Депо

1. Функция «ПринятьПакетОтчётаИзИЦ» — приём, распаковка
2. Создание ТехОперации (комментарий «Отчёт в спец. депозитарий»)
3. Формирование winf.xml (SUBJECT = NTED#report)
4. Создание W-пакета, ИсходящегоПакета, записи РС
5. Доработка обработки квитанций — не падать для не-РСВ
