🔄 Описание бизнес-процесса

1

Инициация работы

Разработчик создает изменения на рабочем компьютере, используя локальный Git-репозиторий

2

Отправка в GitLab

Изменения отправляются через git push в центральный репозиторий GitLab

3

Мониторинг безопасности

Служба безопасности автоматически отслеживает весь трафик GitLab, логирует операции

4

Клонирование в ВМ

Виртуальная машина Яндекс клонирует репозиторий из GitLab для работы с Cursor AI

5

Разработка с Cursor

В ВМ выполняется разработка с использованием Cursor AI для генерации и оптимизации кода

6

Возврат в GitLab

Готовый код коммитится и отправляется обратно в GitLab через git push

7

Синхронизация

Разработчик получает изменения на рабочую машину через git pull

🛡️ Безопасность и мониторинг

Механизмы безопасности

  • Мониторинг трафика: Все операции с GitLab логируются и отслеживаются службой безопасности
  • Аудит операций: Полная история коммитов, пушей и пуллов доступна для анализа
  • Контроль доступа: GitLab обеспечивает разграничение прав доступа к репозиториям
  • Шифрование: Все соединения с GitLab используют HTTPS/SSH с шифрованием
  • Обнаружение аномалий: Система оповещений предупреждает о подозрительной активности

📋 Что отслеживается службой безопасности:

  • Все операции git push/pull/clone
  • IP-адреса источников запросов
  • Время и частота операций
  • Размер передаваемых данных
  • Пользователи, выполняющие операции
  • Ветки и теги, с которыми работают

🌍 Мировые практики и аналоги

GitOps workflow

Наш процесс основан на принципах GitOps - методологии, где Git является единственным источником истины для инфраструктуры и кода. Это стандартная практика в таких компаниях как:

  • Google Cloud Platform: Использует GitOps для управления Kubernetes кластерами
  • Microsoft Azure: Azure DevOps с Git-репозиториями и виртуальными машинами для разработки
  • Amazon AWS: CodeCommit + EC2 instances для удаленной разработки
  • GitHub Codespaces: Прямой аналог - облачная разработка через Git-репозиторий

Remote Development Environments

Использование виртуальных машин для разработки - это стандартная практика в крупных IT-компаниях:

  • GitHub Codespaces: Облачные окружения разработки, подключенные к Git-репозиториям
  • Gitpod: Автоматизированные облачные среды разработки на базе Git
  • JetBrains Space: Интеграция Git-репозиториев с облачными IDE
  • Google Cloud Shell: Облачная среда разработки с доступом к Git-репозиториям

Security Monitoring в Git-системах

Мониторинг трафика GitLab/GitHub - стандартная практика корпоративной безопасности:

  • GitLab Security Dashboard: Встроенные инструменты мониторинга и аудита
  • GitHub Advanced Security: Анализ кода, зависимостей и секретов
  • Azure DevOps Security: Аудит всех операций с репозиториями
  • Bitbucket Data Center: Расширенное логирование и мониторинг

✅ Преимущества данного подхода

🔒 Безопасность

Все операции проходят через контролируемый GitLab, что обеспечивает полную прозрачность для службы безопасности

☁️ Гибкость

Разработка может вестись как на рабочей машине, так и в облачной ВМ, в зависимости от задач

Использование Cursor AI в ВМ позволяет ускорить разработку без установки на рабочие компьютеры

📊 Аудит

Полная история всех изменений хранится в GitLab, что обеспечивает возможность отслеживания и отката

🔄 Синхронизация

Автоматическая синхронизация между рабочими машинами и ВМ через GitLab

⚡ Производительность

ВМ Яндекс обеспечивает мощные вычислительные ресурсы для работы с AI-инструментами

📝 Технические детали

Команды Git для работы с процессом

На рабочем компьютере:

# Отправка изменений в GitLab
git add .
git commit -m "Описание изменений"
git push origin main

# Получение изменений из GitLab (после работы в ВМ)
git pull origin main

В виртуальной машине Яндекс:

# Клонирование репозитория
git clone https://gitlab.tech.nrb/tech/achm_cursor.git
cd achm_cursor

# Работа с Cursor AI, внесение изменений
# ... разработка ...

# Отправка изменений обратно в GitLab
git add .
git commit -m "Изменения через Cursor AI"
git push origin main

Настройка мониторинга безопасности

Для отслеживания трафика GitLab служба безопасности может использовать:

  • GitLab Audit Events: Встроенная система аудита GitLab
  • Webhook-уведомления: Автоматические уведомления о событиях в репозитории
  • API мониторинг: Отслеживание через GitLab API
  • Логи сервера: Анализ логов доступа к GitLab серверу
